# Integrated renderer workload (#1338)

`IntegratedRenderer.olo` is generated by `scripts/perf/generate-integrated-benchmark.py`
from the current AnimalPopulation, Meadow, Courtyard light and OceanCoast scenes.
It includes moving animals, procedural terrain, alpha-masked foliage, four local
lights, directional shadows and a small water patch. A manifest moves one local
light and one featured animal on closed-form sinusoidal paths. The moving camera
and rapid turn are separate phases. The source AnimalPopulation grooms remain
unbound to the Fox bodies and look like blobs; this is a workload limitation,
not evidence of production groom quality.

## Capture protocol

Generate the committed scene and manifests after modifying their source scenes:

```powershell
python scripts/perf/generate-integrated-benchmark.py
```

The four native manifests are `integrated-forward.yaml`,
`integrated-forward-plus.yaml`, `integrated-deferred.yaml` (all OpenGL and
Vulkan), and `integrated-hybrid.yaml` (Vulkan). Each pins a renderer-support
preset ID per backend, native 1920×1080,
MSAA 1, spatial upscale Off, a 64-frame warm-up per camera and 180 measured
frames per phase. The deadline is 33.333 ms. The capture frame follows the
measurement interval, so Beauty and AOVs align to that phase's final pose.
The three scenarios are stationary, dolly and rapid turn. `EntityMotion` advances
at the manifest's fixed time step on the GL test host; the live editor advances
the authored pose once per observed frame, with a real scene clock.
Generated `*-msaa4.yaml` and `*-upscale-quality.yaml` manifests are diagnostic
variations of those native presets. Run them separately for the MSAA and
non-native spatial upscale axes. MSAA variation is generated only for Deferred;
the capture schema applies the sample count to its G-Buffer. The native preset
name in each variation identifies its baseline contract, not an assertion that
the varied setting is a production preset.

For three independent OpenGL processes, from the repository root:

```powershell
python scripts/perf/integrated-benchmark.py --capture-gl `
  --exe build-cached/OloEngine/tests/Debug/OloEngine-Tests.exe `
  --manifest OloEditor/assets/benchmark/manifests/integrated-deferred.yaml `
  --build-config Debug --compiler clang-cl `
  --output OloEditor/assets/benchmark/captures/integrated-deferred-runs
```

Repeat with `integrated-forward.yaml`. A process exit without `result.json` is
a failed run. The driver keeps stdout, stderr, host environment and raw capture
files for every run. Run directories are ignored by Git. A measured production
budget must come from these runs on the named GPU, not from the deadline alone.
`host.json` records capture duration and pre/post GPU graphics clock,
utilization, used memory, temperature and power, so shared-host interference
and throttling can be spotted. An unavailable probe says so explicitly.
It marks the test host's presentation as `offscreen` and VSync as
`not-applicable`.
For a cold shader-cache run, add `--cache-mode cold`: each invocation gets a
fresh empty `run-NN/shader-cache` directory via `OLO_SHADER_CACHE_DIR`, without
deleting a shared cache. For warm-cache runs, pass `--cache-mode warm` and
`--shader-cache-dir <absolute-existing-cache-dir>`; all runs reuse that path.
`host.json` records cache mode, selected path and file counts before/after.
Compare like cache states across presets.

For Vulkan, launch a visible editor with `--rhi=vulkan`, then invoke
`olo_benchmark_capture` with `manifest` set to
`assets/benchmark/manifests/integrated-deferred.yaml` or
`assets/benchmark/manifests/integrated-hybrid.yaml`, and a distinct `outDir`
for each of at least three invocations. Each invocation opens the scene again:
capture the first after a fresh editor launch as cold traversal, and subsequent
ones as warm scene reloads. Record launch flags, build configuration, compiler,
GPU driver, OS, CPU, RAM, resolution, VSync/present mode, shader cache state,
RT device capability and every capture's commit SHA.
Pass a JSON environment record with `--environment-json` when analyzing live
captures; without one, presentation and VSync remain explicitly `unknown` in
`summary.json` and the environment criterion is incomplete.

Set `OLO_SHADER_CACHE_DIR` **before** launching the Vulkan editor. Use a new,
empty directory for a cold process and a named reused directory for warm
processes; preserve both directories with the result provenance. A warm scene
reload inside one editor process retains additional process resources, so label
it separately from a warm shader cache in a fresh process.

Summarize the three output directories with:

```powershell
python scripts/perf/integrated-benchmark.py `
  --run-dir OloEditor/assets/benchmark/captures/vk-run-01 `
  --run-dir OloEditor/assets/benchmark/captures/vk-run-02 `
  --run-dir OloEditor/assets/benchmark/captures/vk-run-03 `
  --output OloEditor/assets/benchmark/captures/vk-analysis
```

The editor host may time out a warm-up or measurement wait; such a result is
retained for inspection but rejected by the analysis script. The editor host's
per-frame marshals can perturb timing, so do not pool its values with the GL
test host's `Scene::OnUpdateEditor` call duration. The GL metric excludes
present, editor UI, and attachment readback. Neither metric is end-to-end
player frame time. Scene loading and process startup are outside the sampled
window; the GL driver separately records full process elapsed time.

## Reading the result

`result.json` contains per-scenario p50/p95/p99/max and deadline misses.
`measurement.csv` retains every frame, CPU and fence/present waits, tracked
renderer bytes, and GPU timing status plus frame ID. GPU samples resolve late;
only `valid` values with distinct frame IDs can be aggregated. A valid black
pixel or zero GPU duration is not absence. The analysis script reports a range
of each statistic across independent runs; it does not bootstrap adjacent
frames as if they were independent. CPU, fence wait and present wait have their
own distributions; the GPU distribution includes only valid unique frame IDs.

The tracked memory total includes both CPU and GPU allocations. Observed peak
and live totals are available. The GL host also records the tracked total after
releasing its scene, with renderer and asset caches still alive. Isolated GPU
memory and pooled/history/AS retention remain **unknown**; the retention
breakdown in #1338 is not yet met. Likewise, the capture records requested and
selected settings but does not prove technique production or consumption;
inspect pass counters, GPU Scene and RT fallback telemetry with the live
capture. The live-editor crop under a non-native upscale mode (#1397) is fixed, so an
upscale A/B now keeps the native framing; the capture itself still refuses a
sub-scale `RenderScale`. AOV coverage and moving-light pixels
must be inspected in live captures before calling a scenario representative.
