# The msvc and clangcl build trees must never run concurrently — and how to actually run Windows ASan locally

Operational rules for the `build/` (msvc) and `build-clang/` (clangcl / clangcl-asan) trees, Windows ASan, build instrumentation, the compiler cache and cross-worktree build concurrency. Read before building, touching CMake build wiring, or debugging a Windows or sanitizer CI failure.

## Rules

1. **Sequence the msvc and clangcl trees: finish or stop any build in one before starting the other,** including background builds from an earlier turn (check for live `MSBuild`/`ninja`/`cl` processes). Both run `GenerateBindings`, and `mspdbsrv` is shared. After mixing trees, LNK2038/LNK1319 is fixed by `cmake --build build --target bc7enc --config Debug --clean-first`. [Details](build-trees-and-windows-asan-details.md#1-never-run-the-two-build-trees-at-the-same-time)
2. **A build hung with hours of wall time and seconds of CPU is a wedged `mspdbsrv.exe`.** Check CPU with `Get-Process cl`; verify no compiler is genuinely working, then `Stop-Process -Name mspdbsrv -Force`, kill surviving `cl.exe`, `Stop-Process -Name MSBuild -Force`, delete the `.pdb`, rebuild. Set `MSBUILDDISABLENODEREUSE=1` for agent builds. [Details](build-trees-and-windows-asan-details.md#1a-mspdbsrv-is-per-user-not-per-worktree--one-wedged-instance-stalls-every-build-on-the-box)
3. **When changing the `GenerateBindings` build wiring, re-measure no-op builds on both generators; a green build proves nothing.** The stamp is the sole OUTPUT (never `BYPRODUCTS`: `clean` deletes the tracked generated files), a `#` or `$` in a depfile path is unrepresentable, no directories in a depfile (use a `CONFIGURE_DEPENDS` glob manifest), and `CODEGEN` does nothing unless the output is consumed by a compiled target in the same directory. Force regeneration by deleting the stamp, never the generated sources. [Details](build-trees-and-windows-asan-details.md#1b-build-graph-integrating-a-codegen-tool-four-traps-all-silent-issue-758)
4. **Build `clangcl-asan` with `--config Release`, never Debug** (clang-cl rejects ASan with the debug CRT), and give `--parallel` a number. Put `C:\Program Files\LLVM\lib\clang\<version>\lib\windows` on PATH before running anything instrumented (exit `0xC0000135` means a DLL is missing; the MSVC-bundled ASan runtime gives `0xC0000139`). `steam_api64.dll` must sit beside the executable. [Details](build-trees-and-windows-asan-details.md#2-building-and-running-the-clangcl-asan-preset-locally)
5. **Run a failing ASan test with `--gtest_catch_exceptions=0`** to get ASan's report instead of an opaque `SEH exception with code 0xc0000005`. [Details](build-trees-and-windows-asan-details.md#2-building-and-running-the-clangcl-asan-preset-locally)
6. **A green msvc build is not evidence the sanitizer CI compiles; Clang is stricter.** Do not use a nested class's default member initializers in an enclosing class's default argument; define the struct at namespace scope and alias it. Pre-push, syntax-only compile touched TUs with `clang-cl ... /clang:-fsyntax-only` using the msvc tree's include dirs (Windows source path, `MSYS2_ARG_CONV_EXCL='*'`, tests-project include dirs for test or `OloEditor/src/MCP` TUs), and confirm the check fails with the fix stashed. [Details](build-trees-and-windows-asan-details.md#2b-a-green-msvc-build-is-not-evidence-the-sanitizer-ci-will-compile)
7. **If a fresh worktree's first `cmake --preset msvc` fails on `gamenetworkingsockets-src`, look for orphaned `git.exe` processes** (`tasklist /FI "IMAGENAME eq git.exe"`), or `robocopy <sibling>\OloEngine\vendor\gamenetworkingsockets-src <this>\... /MIR /MT:16`, delete the stale `gamenetworkingsockets-subbuild`/`-build` dirs and reconfigure. Robocopy exit codes 0-7 are success; 8 or higher is failure. [Details](build-trees-and-windows-asan-details.md#3-a-fresh-worktrees-first-cmake---preset-msvc-can-wedge-on-the-gamenetworkingsocketswebrtc-vendor-clone)
8. **Pin the LLVM version in any Windows clang-cl job; do not guard a throwing test out of the ASan build.** An `SEH exception with code 0xc0000005` with no ASan report: first check which clang resolved (`clang-cl --version` locally; `asan.yml` pins 23.1.0 by absolute path), not whether the engine regressed. Check what a skipped throw leaves vacuous, and that existing malformed-input tests actually reach a `throw`. [Details](build-trees-and-windows-asan-details.md#4-fixed-toolchain-bug-c-throws-through-instrumented-frames-used-to-av-issue-661)
9. **Never throw from inside a `catch` handler in code the Windows ASan build compiles.** Capture the exception and rethrow after the handler, or use RAII rollback. `cmake/Sanitizers.cmake` adds `-fsanitize-address-use-after-return=never` as a mask only; the throw type, rethrow form and `/Ob0` do not matter. [Details](build-trees-and-windows-asan-details.md#4b-live-toolchain-bug-a-throw-from-inside-a-catch-handler-avs-clang-cl--asan)
10. **On a PR-only Windows-ASan `0xc0000005`, run `git merge-base --is-ancestor 8e5050ad4 <branch>` before reading code;** master skips its Windows shards, so it is not a control, and rebasing was the fix. [Details](build-trees-and-windows-asan-details.md#a-masked-site-still-crashes-on-a-branch-cut-before-the-mask-2026-09-11)
11. **Instrument a build with `cmake --preset clangcl -DOLO_BUILD_INSTRUMENTATION=ON` on CMake 4.3+ (Ninja tree only, never `build/`).** Verify the `ctest.exe --instrument` prefix in `rules.ninja`; only the latest trace is kept. For per-TU memory use `OLO_PROC_STAT_REPORT` and `build-memory-per-tu.md`. [Details](build-trees-and-windows-asan-details.md#5a-use-the-native-recipe-cmake-43-not-the-manual-gate-below)
12. **Heavy TUs go through `olo_bind_heavy_compile_pool()`** (`olo_heavy` pool, depth 2, `-DOLO_HEAVY_COMPILE_JOBS=<N>`); file-set `FILES` resolve against the caller's directory, so resolve against `base_dir` explicitly. Measure with `--target OloEditor --target OloEngine-Tests` together. [Details](build-trees-and-windows-asan-details.md#5d-the-heavy-compile-file-set-pool-cmake-44-issue-822)
13. **Both memory pools (`OLO_LINK_JOBS`, `olo_heavy`) are Ninja-only; on Linux CI the `--parallel N` you pass is the only cap.** A bare `--parallel` is unbounded under Unix Makefiles, so audit it together with the job's generator. Copy `steam-stub.yml` for a new Linux job, set `CMAKE_BUILD_TYPE` at configure time (`--config` is ignored), and use `./.github/actions/setup-llvm-apt` instead of hand-rolling the apt step. [Details](build-trees-and-windows-asan-details.md#5e-both-memory-pools-are-ninja-only--so-on-linux-ci---parallel-n-is-the-only-cap-issue-796)
14. **Keep `/showIncludes` forced for MSVC-frontend compilers behind a compiler cache** (`cmake/CompilerCache.cmake`); clang-cl's gcc-style depfile through ccache leaves `#deps 0` and stale objects. `depend_mode = true` does not fix it. Do not measure with `ninja -n`; count `ninja -t deps` records. [Details](build-trees-and-windows-asan-details.md#6-a-compiler-cache-in-front-of-clang-cl-can-leave-ninja-with-no-header-dependencies-issue-858)
15. **Check a cached tree with `scripts/Check-NinjaHeaderDeps.ps1`; never allowlist an untraceable object.** Pass `-Config`; `build-lock.ps1` runs it after each successful cached build. [Details](build-trees-and-windows-asan-details.md#the-check)
16. **When adding or retuning a compiler launcher, confirm everything the build tool reads besides the object survives a cache hit** (depfile, `/showIncludes`, pdb). [Details](build-trees-and-windows-asan-details.md#what-this-generalises-to)
17. **Keep every worktree in `C:\repos` and the ccache `base_dir` pointing there;** a worktree outside it caches only itself, silently. Default to the `build-cached` tree (the Visual Studio generator ignores compiler launchers), pin `OLO_COMPILER_CACHE_TOOL` to an absolute path, set `base_dir` and `hash_dir=false`. [Details](build-trees-and-windows-asan-details.md#7-the-compiler-cache-only-shares-between-worktrees-under-its-base_dir)
18. **`build-lock.ps1` grants a second concurrent build only for cached Ninja trees with free memory above `-ConcurrentMinFreeGB` (default 24);** `-MaxConcurrent 1` restores one at a time. A `build/` tree never qualifies; `cmake/LinkSemaphore.cmake` bounds links with `OLO_LINK_SEMAPHORE_SLOTS` (default 2) OS-named mutexes, not a semaphore. [Details](build-trees-and-windows-asan-details.md#8-build-concurrency-across-worktrees-the-second-slot-and-why-the-link-bound-is-n-mutexes)
19. **Outside the lock, always pass an explicit job count (`-j6` is the conservative default; `-j12` is safe on an idle box);** dropping the number raises the width to Ninja's `cores + 2`. [Details](build-trees-and-windows-asan-details.md#8-build-concurrency-across-worktrees-the-second-slot-and-why-the-link-bound-is-n-mutexes)

## Commands and checks

Syntax-only pre-push check for a touched TU (Windows source path):

```bash
export MSYS2_ARG_CONV_EXCL='*'
"/c/Program Files/LLVM/bin/clang-cl.exe" /std:c++latest /EHsc $INC /clang:-fsyntax-only /clang:-w /TP /c 'C:\path\to\Changed.cpp'
```

Header-dependency check for a cached tree:

```powershell
pwsh -File scripts/Check-NinjaHeaderDeps.ps1 -BuildDir build-cached
```
