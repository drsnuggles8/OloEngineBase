# Vulkan parallel command recording: the threading model, and how a pass opts in

Covers how a pass records independent work items on task workers via `RenderCommand::RecordParallel(count, body)`, what state is per thread and what is per process, and the checklist for converting a pass. The contract is ADR 0011 amendments (92) and (94); issues #806 and #1013. Pass coverage: [vulkan-parallel-pass-audit.md](vulkan-parallel-pass-audit.md).

## Rules

1. **Give every item its own resource objects and write only item-owned state.** Command-buffer state lives in a `VulkanRecordingContext` selected through a thread-local; process-wide backend state is frozen or mutex-protected. See the ownership table. [Details](vulkan-parallel-recording-details.md#1-what-is-per-thread-what-is-per-process)
2. **Find every written object and give each item private upload objects created before the region.** UBO/SSBO `SetData` and `InstanceBuffer::Upload` version bytes per object (amendments (78), (80)); shadow views own camera, animation and instance buffers. [Details](vulkan-parallel-recording-details.md#4-converting-a-pass-the-checklist)
3. **Audit transitive shared state.** Search for `static`, `s_`, `GetInstance`, `::Get()` and lazy per-object builders (`VulkanShader::GetRootDataLayout` needed guarded first construction). Shadow foliage takes time as a frozen argument and uses the item's foliage UBO. [Details](vulkan-parallel-recording-details.md#4-converting-a-pass-the-checklist)
4. **Publish every shader-dependent choice on the item's own thread when it binds a shader.** A render-thread-only bind flag is not a valid source for worker material uploads (#1424: zero material offsets because the worker bind returned before setting the flag). `VulkanShader::Bind` publishes `Shader::ReadsMaterialHeapOffsets` on every recording thread. [Details](vulkan-parallel-recording-details.md#1-what-is-per-thread-what-is-per-process)
5. **Test for a set worker context, not for the render thread.** `Ctx()` reads `CurrentVulkanWorkerContext()` installed by `ScopedVulkanWorkerContext`, and the caller also runs items through `ParallelFor`. [Details](vulkan-parallel-recording-details.md#1-what-is-per-thread-what-is-per-process)
6. **Do not rely on what an item wrote into its private upload object after the join.** The copy is seeded at the fork and never copied back; inline leaves the last iteration's bytes, the fork path leaves the pre-fork bytes. Re-upload after the region or keep the write out of the item. `Publish()` clears the dispatcher bind caches for this reason. [Details](vulkan-parallel-recording-details.md#4-converting-a-pass-the-checklist)
7. **Size buffers before the fork.** Resource creation and reclamation are refused on items, so prepare capacity for the largest batch an item can upload. [Details](vulkan-parallel-recording-details.md#4-converting-a-pass-the-checklist)
8. **Order the clears.** A clear covering what several items share goes before the fork; a clear on one item's own subresource goes inside that item. Atlas entries share layer zero, so transition that attachment and materialise its clear before forking; clearing inside an atlas item erases other entries' tiles. Regions whose items select their own targets (cascades) rely on disjoint targets. [Details](vulkan-parallel-recording-details.md#3-the-layout-rule-and-the-pre-transition-that-makes-shared-targets-legal)
9. **Make every write to a shared subresource preserve its layout.** Barriers read `oldLayout` from the frozen base. `VulkanLayoutClaimTable` rejects incompatible claims with both item indices; overlay merge reports conflicts via `ParallelRecordingFrameStats::MergeConflicts` and MCP. Every conflict is a pass bug. [Details](vulkan-parallel-recording-details.md#3-the-layout-rule-and-the-pre-transition-that-makes-shared-targets-legal)
10. **Get sampled textures into their read layout before the fork.** Declare them as graph reads or bind them once before the fork; the fork cannot discover textures that exist only in packets until replay. A texture written earlier and first sampled in two items is a layout conflict; join between a shared write and a later sampling region. [Details](vulkan-parallel-recording-details.md#4-converting-a-pass-the-checklist)
11. **Never target the backbuffer, query, read back, flush or create resources inside an item.** Each is refused (Debug asserts, otherwise warn-once); frame-scoped dispatcher setters reject item calls; a buffer written by two items asserts at the second `SetData`; GPU timestamp scopes belong outside worker bodies. [Details](vulkan-parallel-recording-details.md#4-converting-a-pass-the-checklist)
12. **Keep item bodies independent of iteration order.** Every item starts from the fork's seed; establish item-local shader/mode caches at the start of every body, including on the inline path where backend state carries over. Blended draws may use contiguous ranges of the sorted packet stream. [Details](vulkan-parallel-recording-details.md#4-converting-a-pass-the-checklist)
13. **Keep fork, merge and execute in item order, and rebind descriptor heaps at once after execute.** Overlays merge, secondaries execute (one `vkCmdExecuteCommands`) and tallies/statistics publish in item order; after execute the primary's caches are reset and heaps rebound before any copy or clear the next pass records (#1511). [Details](vulkan-parallel-recording-details.md#2-the-fork-the-join-and-why-the-order-is-what-it-is)
14. **Verify on both backends.** OpenGL runs the same code inline. A Vulkan frame with `OLO_VK_PARALLEL_RECORDING=0` (forces inline) must match one with it on, and the validation layer must stay clean. [Details](vulkan-parallel-recording-details.md#4-converting-a-pass-the-checklist)
15. **Measure speedup in Release only.** Debug validates correctness; MSVC debug iterators serialise containers on a global lock. Compare interleaved off/on runs with an untouched control pass and report the control's drift. [Details](vulkan-parallel-recording-details.md#5-what-a-measurement-in-a-debug-build-tells-you)
16. **Expect inline execution without a begun frame.** Secondary pools reset with `VulkanFrameArena`'s generation and `BeginFrame(slot)` only follows that slot's fence; headless fixtures use the same clock. [Details](vulkan-parallel-recording-details.md#6-where-the-frame-clock-comes-from)
17. **Respect the bucket replay limits.** `CommandBucket::ExecuteParallel` / `RecordPackets` use contiguous ranges of at least 32 packets per item and at most `MAX_RENDER_WORKERS` items; any rejected packet (query-bearing mesh, observed decal, unsupported kind) keeps the whole span inline. Compute instance capacity before the fork. [Details](vulkan-parallel-recording-details.md#7-bucket-replay-and-region-diagnostics)
18. **Whole-pass recording follows its own contract.** See [vulkan-parallel-graph-recording.md](vulkan-parallel-graph-recording.md) for prepared passes, topological grouping, fences and ordered publication. [Details](vulkan-parallel-recording-details.md#8-whole-pass-recording)
19. **Leave the main context exactly as the inline loop would at the join.** The join publishes the last item's front-end caches, its framebuffer selections and its binding state; a cache describing one binding while `VulkanBindingState` holds another makes a later bind-if-needed skip a bind that never happened. [Details](vulkan-parallel-recording-details.md#9-the-join-must-leave-the-inline-loops-state)

## Commands and checks

```
OLO_VK_PARALLEL_RECORDING=0     # forces inline recording, for off/on comparison
OLO_VK_RECORDING_COSTS=1        # adds selectionSeedMs, attachmentPrepareMs, sampledImagePrepareMs, pipelineLookupMs per region
```

Leave `OLO_VK_RECORDING_COSTS` unset for the final off/on frame-time comparison. `olo_perf_pass_timings` shows region decisions and timings.
