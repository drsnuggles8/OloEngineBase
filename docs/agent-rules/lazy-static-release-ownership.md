# Release a shared lazy static from the teardown that always runs, not from the one that happened to draw with it

Rules for where a GPU-owning static, singleton or per-frame recording state is released (issues #814, #839, #1226). A release in the wrong teardown leaks invisibly on GL and aborts the Vulkan allocator teardown (in Debug, a hang on the VMA assert dialog).

## Rules

1. **Release from the narrowest teardown that is unconditional for every session that can create the object, and that runs while the graphics context is alive.** 3D-only facility: `Renderer3D::Shutdown()` (it runs only `if (Renderer3D::HasInitialized())`). Other `Renderer/` objects: `Renderer::Shutdown()`. Backend-private GL object: `OpenGLRendererAPI::ShutdownGpuResources()`. Non-renderer subsystem owning GPU memory: `Application::~Application()` after `Project::Unload()` and before `Renderer::Shutdown()`. State for one call: the end of that call. [Details](lazy-static-release-ownership-details.md#the-rule-one-level-up)
2. **Do not put a release for a warmup-reachable facility in `Renderer3D::Shutdown()`.** `Renderer::Init()` always runs `ShaderWarmup::Init()` and `Renderer2D::Init()`, which can create `MeshPrimitives::GetFullscreenTriangle()`; `OloRuntime` can exit before 3D init. Releasing where it is created is equally correct. [Details](lazy-static-release-ownership-details.md#the-shape-stated-generally)
3. **Release before `RenderCommand::ShutdownGpuResources()`, never after the context is gone.** Moving a release later in `Renderer::Shutdown` is safe on both backends. [Details](lazy-static-release-ownership-details.md#the-rule)
4. **Treat a lifetime bug found on Vulkan as a GL bug too.** GL has no allocator-teardown assertion, so only detection is Vulkan-only. Run a GL-side pass for leak classes found on Vulkan (e.g. the `OpenGLTextureCubemap` staging `GL_PIXEL_UNPACK_BUFFER`). [Details](lazy-static-release-ownership-details.md#the-rule)
5. **Run three sweeps, not one.** (1) Every process static holding a `Ref<T>` where `T` owns GPU memory: does its own TU reset it? (2) Every `Shutdown()` / `Release*()` on a static or facility: who calls it? (`VideoSystem::Shutdown()` and `GPUTimerQueryPool::Shutdown()` had no caller.) (3) Every raw `static GLuint` / `static Vk*` in the platform layers: is there a matching delete? [Details](lazy-static-release-ownership-details.md#the-sweep-839-what-the-rest-of-the-class-looked-like)
6. **Clear a scratch static at the end of the call that uses it, with a scope guard.** `SceneHierarchyPanel.cpp`'s file-scope `Ref<Scene> s_DrawComponentScene` pinned the last drawn scene for the process (the leak only appeared once an entity was selected). Look for an extra owner before reordering teardown; reordering turns a leak into a use-after-free. [Details](lazy-static-release-ownership-details.md#the-big-one-was-not-a-teardown-placement-bug-at-all)
7. **Remember a snapshot is a copy of the component.** `DrawComponent<T>`'s static edit-state maps (`ComponentEditTracker`) pinned `Ref<Model>` / `Ref<Texture2D>` until cleared. A declaration scan cannot see a `Ref` inside a container's mapped type. [Details](lazy-static-release-ownership-details.md#the-one-the-guard-cannot-see-and-how-it-was-found)
8. **Never store a strong `Ref` back to the owner from an embedded member.** `ShaderResourceRegistry::m_Shader` held a strong `Ref<Shader>` to its enclosing `OpenGLShader` (115 surviving GL shader programs, #841); it now holds a non-owning `const Shader*`. Check for self-cycles when a GPU-owning object survives every release call. If a rebuild seems to disprove a correct fix, suspect stale incremental builds ([incremental-build-odr-staleness.md](incremental-build-odr-staleness.md)). [Details](lazy-static-release-ownership-details.md#841-resolved-not-a-species-this-documents-scan-covers-and-not-a-code-bug-at-all)
9. **Release per-frame recording state where every owner reaches teardown.** `VulkanRendererAPI::m_Items` clones (camera UBO, bone palette, `InstanceBuffer`) are released in `VulkanDevice::Shutdown`, with the deferred-reclaim drain after them and before the allocator goes down, not only via `CommandDispatch::Shutdown() -> RenderCommand::ReleaseParallelRecordingResources()` (#1226). [Details](lazy-static-release-ownership-details.md#the-same-rule-one-level-up-per-frame-recording-state-not-just-lazy-statics)
10. **Keep GL headers out of engine-core TUs.** Do not call a function from `OpenGLTextureCubemap.h` in `Renderer.cpp`: it includes `<glad/gl.h>` and the ratchet (`sweep_glad_includes == 0`, `RHIBoundaryRatchetTest`) counts only direct includes, so it would not notice. [Details](lazy-static-release-ownership-details.md#the-rule-one-level-up)
11. **Keep the guards honest.** `RendererShutdown.WarmupReachableFacilitiesAreReleasedBySubsystemNeutralShutdown` accepts `Renderer::Shutdown()` plus `Renderer2D::Shutdown()` and `ShaderWarmup::Shutdown()`, and starts from the seeded roster `kEngineWideFacilities`; its reachability scan is one-hop textual. `RendererShutdown.EveryProcessStaticGpuResourceHasAReleaseSite` covers direct declarations only, seeded by `kGpuOwningRefTypes` and the scanned extensions (`.cpp/.cc/.cxx`, `.h/.hpp/.hh/.inl`); neither an initializer's `= nullptr` nor an out-of-class static definition counts as a release. [Details](lazy-static-release-ownership-details.md#guard)
12. **Red-check a source-scanning guard against every way the invariant can break, in the compiled binary.** Delete the release and rerun the built binary (no rebuild); a regex change that shifts capture groups can silently skip a whole branch. [Details](lazy-static-release-ownership-details.md#the-guard-and-what-it-deliberately-does-not-cover)
13. **Find species (c) empirically.** No cheap static guard finds a release nothing calls. Use the Vulkan teardown forensics (#794) and `RendererMemoryTracker::Shutdown()` (OpenGL resource classes only; `Renderer::Init()` calls its `Initialize()`). [Details](lazy-static-release-ownership-details.md#the-guard-and-what-it-deliberately-does-not-cover)
14. **Run the teardown under `cdb` before believing a leak count, and read the console.** The VMA leak assert aborts and drops spdlog's buffered tail; a nonzero exit code with an early-ending `OloEngine.log` is that abort, not a second bug. `sxe av` proves there is no access violation. [Details](lazy-static-release-ownership-details.md#the-one-the-guard-cannot-see-and-how-it-was-found)
15. **Name allocations with identifying data and put forensics on the failing path.** Name storage buffers with binding and size (`binding=15, 256B`), not the class name; call `LogSurvivingVertexArrays` / `VulkanLogSurvivingTransients` on every teardown path that can hit the assert. [Details](lazy-static-release-ownership-details.md#the-same-rule-one-level-up-per-frame-recording-state-not-just-lazy-statics)
16. **A test that must release a subsystem's static by hand shows the release site is misplaced.** `VulkanPassSuiteTest` calls `MeshPrimitives::Shutdown()` for this reason. [Details](lazy-static-release-ownership-details.md#guard)

## Commands and checks

Reproduce the no-start-scene Vulkan leak from the repo root (`-WorkingDirectory` is a `Start-Process` parameter, not an OloRuntime flag; it does not move the session's working directory). Needs `assets/shaders` and `assets/fonts` but no `Scenes/` or `game.manifest`; exit code is 0 once fixed; read `OloEditor/OloEngine.log`:

```powershell
$p = Start-Process -FilePath .\bin\Debug\OloRuntime\OloRuntime.exe `
                   -WorkingDirectory .\OloEditor `
                   -ArgumentList '--rhi=vulkan' -PassThru -NoNewWindow
if (-not $p.WaitForExit(60000)) { $p.Kill(); $p.WaitForExit() }
"$($p.ExitCode)"
```
