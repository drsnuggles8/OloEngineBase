# Camera-relative rendering — every world-space GPU upload is a site (issue #429)

Rules for any code that sends a world position or world-space matrix to the GPU. Every world-space value is shifted by a per-frame render origin `O` (camera position snapped to a `kRenderOriginGridSize` grid, default 1024) so the GPU works near 0 where f32 is precise. Helpers: `Renderer/CameraRelative.h` (`ComputeRenderOrigin`, `MakeModelRelative`, `MakeViewRelative`, `MakeViewProjectionRelative`, `MakePositionRelative`). A missed site is silent near the origin.

## Rules

1. **Verify a new world-space upload far from the origin.** Within the first grid cell `O == (0,0,0)` exactly, so every shift is a byte-identical no-op and a missed site shows only at tens of km. Use the visual before/after in `CameraRelativeVisualEvidenceTest.cpp`; math is pinned by `CameraRelativeTest.cpp`. [Details](camera-relative-rendering-details.md#the-one-invariant-to-internalise)
2. **Classify a new upload by what it is.** Object/model matrix: `MakeModelRelative` (translation -= O). Matrix that consumes world positions (view, view-projection, light-space): `MakeViewProjectionRelative`. Bare world position, AABB corner or light position: `- O`. [Details](camera-relative-rendering-details.md#the-rule-when-you-add-a-new-world-space-gpu-upload)
3. **Add `u_RenderOrigin` back in-shader for absolute-world patterns (family A).** Triplanar tiling, procedural noise, world-anchored wave phase, wind field and grid/clipmap shaders compute `absWorldPos = v_WorldPos + u_RenderOrigin`. Never interpolate the absolute position across a triangle. Patterns whose period divides 1024 need nothing. [Details](camera-relative-rendering-details.md#a-interpolated-world-position--relative--add-o-back-for-patterns)
4. **Add `u_RenderOrigin` to every shader's own inline camera block.** It is the trailing member of the `CameraMatrices` block (binding 0), after `u_PrevViewProjection`, std140 offset 272 (`ShaderBindingLayout::CameraUBO`, 288 B; `CameraCommon.glsl`). Full blocks append `vec3 u_RenderOrigin; float _padding1;`; truncated blocks add the missing `u_PrevViewProjection` tail first; a fragment stage without a camera block gets one, mirroring the vertex block for SPIR-V link validation. [Details](camera-relative-rendering-details.md#a-interpolated-world-position--relative--add-o-back-for-patterns)
5. **Reconstruct depth-based world positions with the world inverse-VP (family B).** `inverse(VP_world) * ndc` gives the absolute position with no add-back (volumetric fog, decals, underwater fog/caustics, motion blur), and world-space UBO inputs (`WorldToLocal`) stay unshifted. Lift the relative `u_CameraPosition` with `+ u_RenderOrigin` for difference terms. [Details](camera-relative-rendering-details.md#b-depth-reconstructed-world-position--use-the-world-inverse-vp--absolute)
6. **Subtract `u_RenderOrigin` after reconstruction when the other inputs are render-relative (family B').** Deferred lighting (`DeferredLighting.glsl`, `_MSAA`, `DeferredLightingShared.glsl`) does `worldPos = ReconstructWorldPosGB(...) - u_RenderOrigin` because camera, lights, Forward+ SSBO, shadow matrices and probe bounds are relative. Volumetric fog's `sampleShadowForFog` subtracts locally before projecting. Give the camera block a distinctly-named padding mat4 so the tail does not collide with binding 8 `u_PrevViewProjection`. [Details](camera-relative-rendering-details.md#b-depth-reconstruction-whose-other-inputs-are-relative--subtract-o-back-to-relative)
7. **Keep world `ViewMatrix`/`ViewProjectionMatrix` on the CPU.** CPU frustum cull, depth sort keys and the planar-reflection mirror need world space; `RenderPipeline::PrepareFrame` computes `RenderOrigin` up front and builds the primary CameraUBO relative. `CommandDispatch::UploadCameraUBO` is the one path for all camera uploads. [Details](camera-relative-rendering-details.md#done--core-camera--matrices--transforms--shadows--lights)
8. **Shift per-object transforms consistently.** `CommandDispatch::UploadModelInstance` and the instanced loop shift `Transform`/`PrevTransform`; `ShadowRenderPass` shifts every caster path; `GPUFrustumCuller::Cull` and the legacy `OcclusionCuller` proxies shift their inputs. [Details](camera-relative-rendering-details.md#done--core-camera--matrices--transforms--shadows--lights)
9. **Upload foliage grass with `translate(-O)` as the model matrix, not identity.** The per-blade VBO holds absolute positions; the foliage shaders add `u_RenderOrigin` back for wind, which is only correct with that model matrix. `Foliage_Depth` needs nothing. [Details](camera-relative-rendering-details.md#done--core-camera--matrices--transforms--shadows--lights)
10. **Make GPU Hi-Z cull's `PrevViewProjection` relative to the same origin.** Use `MakeViewProjectionRelative`, otherwise `VP_world * relativeCenter` mis-culls far from origin. [Details](camera-relative-rendering-details.md#done--core-camera--matrices--transforms--shadows--lights)
11. **Shift shadow sampling and rendering identically.** `ShadowMap::UploadUBO(origin)` shifts sampling matrices and point positions; `ShadowRenderPass::RenderCascadeOrFace` shifts `lightVP`, point `Position` and casters, and sets `RenderOrigin` in the shadow-camera UBO so caster shaders that reconstruct absolute position (`Terrain_Depth.glsl` snow height) match the lit surface. [Details](camera-relative-rendering-details.md#done--core-camera--matrices--transforms--shadows--lights)
12. **Shift lights and probes.** `Renderer3D::UploadMultiLightUBO` and `LightCullingBuffer::Update` shift light positions; `UploadLightProbeData` uses `BoundsMin/Max - O`. [Details](camera-relative-rendering-details.md#done--core-camera--matrices--transforms--shadows--lights)
13. **Feed `Grid()` in the infinite grid shaders `fragPos3D + u_RenderOrigin`.** The GBuffer variant's fragment has no camera block, so the origin rides a `flat` varying from the vertex stage. Water: VS/TES pass absolute position to `sumGerstnerWaves(...)` and subtract `u_RenderOrigin` from the displaced result for `gl_Position`. `SnowCommon.glsl` stays origin-agnostic. [Details](camera-relative-rendering-details.md#done--family-a-geometry-pattern-shaders--u_renderorigin)
14. **Fix `Renderer2D` with a CPU coordinate shift, not a shader change.** It keeps its own `s_Data.RenderOrigin` per `BeginScene`; upload the camera relative via `MakeViewProjectionRelative(vpWorld, O)`; shift transform-matrix `Draw*` calls once with `MakeModelRelative(transform, O)`; explicit-position calls (`DrawLine`/`DrawPolygon`/`DrawQuadVertices`) subtract `O` per vertex with `MakePositionRelative`. [Details](camera-relative-rendering-details.md#done--2d-sprites-renderer2d-cpu-bake--a-coordinate-shift-not-a-shader-change)
15. **Do not double-subtract in `DrawRect(mat4)`.** It bakes corners relative and feeds a private `DrawLineImpl` (no shift); routing them through the public `DrawLine` subtracts `O` twice. Audit any other subsystem that bakes absolute-world vertices outside `Renderer2D`. [Details](camera-relative-rendering-details.md#done--2d-sprites-renderer2d-cpu-bake--a-coordinate-shift-not-a-shader-change)
16. **Evaluate terrain LOD and cull in object-local space through the render origin.** Use `MakeObjectLocalViewProjection(vpWorld, objectWorld, O)` and `MakeObjectLocalCameraPos(cameraWorld, objectWorld, O)`; `Scene.cpp` (`ProcessScene3DSharedLogic`, runtime and editor) builds per-terrain local inputs via `MakeTerrainLocalCullInputs` for `SelectVisibleChunks` and `GetVisibleChunks`. This is not a shift-back; it also fixes any off-origin terrain. Pinned by `TerrainCameraRelativeLODTest.cpp`. [Details](camera-relative-rendering-details.md#done--terrain-geometry-lod--cull-cpu-object-local-space--not-a-shift-back)
17. **Bisect with the debug levers.** `Renderer3D::SetCameraRelativeEnabled(false)` pins `O` to (0,0,0); `Renderer2D::SetCameraRelativeEnabled(false)` is independent (own `s_Data.CameraRelativeEnabled`). 2D is pinned by `Renderer2DCameraRelativeTest.cpp` and `Renderer2DCameraRelativeVisualEvidenceTest.cpp`. [Details](camera-relative-rendering-details.md#debug--bisect-lever)
18. **Know the open gaps.** `TerrainStreamer` tiles render with the entity transform only (per-tile `WorldOrigin` unapplied, no `SelectVisibleChunks` call for tile chunk managers), and floating-origin rebasing with `SceneStreamer` is not done. [Details](camera-relative-rendering-details.md#remaining-follow-up)
