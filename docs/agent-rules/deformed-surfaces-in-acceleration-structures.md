# A ray tracer can only see geometry that is in memory, and skinning is not

From issue #1229. Read before putting animated geometry in an acceleration structure. Extends [vulkan-ray-tracing-acceleration-structures.md](vulkan-ray-tracing-acceleration-structures.md) and borrows the producer in [skeletal-deformation-shared-output.md](skeletal-deformation-shared-output.md).
Code: `Renderer/RayTracing/DeformedSurfaceCache.{h,cpp}`, `Passes/SkeletalDeformPass.{h,cpp}`, `assets/shaders/compute/SkeletalDeformToBuffer.comp`, `RayTracingScene::Classify` and `DecideBuild`.

## Rules

1. **Write the pose to memory before building a BLAS from it.** Raster deforms in the vertex stage and keeps nothing, so a skinned mesh's vertex buffer holds the rest surface; pointing a build at it succeeds and yields a T-posed character in every ray-traced effect. [Details](deformed-surfaces-in-acceleration-structures-details.md#1-the-rule-and-why-it-is-not-obvious)
2. **Reuse `include/SkeletalDeformation.glsl` through `OLO_DEFORM_EXTERNAL_PALETTE`; only the palette storage may differ.** A copy of linear-blend skinning drifts (#1226 removed seven). `SkeletalDeformationContractTest`'s `kSkinnedConsumers` list is closed by `NoShaderOutsideTheListReachesTheProducer`, which also asserts the scan found as many shaders as the list names. [Details](deformed-surfaces-in-acceleration-structures-details.md#2-reuse-the-producer-the-storage-is-the-only-thing-allowed-to-differ)
3. **Divide the deformed position by `w` in the compute shader.** `OloDeformedSurface::Position.w` is the total influence weight, not 1; raster absorbs it in the perspective divide, a vertex buffer does not, so `p/w` is the point raster draws. [Details](deformed-surfaces-in-acceleration-structures-details.md#3-two-things-the-compute-shader-must-do-that-the-vertex-stages-do-not)
4. **Renormalize the deformed normal (do not divide by `w`), and fall back to the rest value on a degenerate result.** A NaN vertex poisons the tree for the whole surface. [Details](deformed-surfaces-in-acceleration-structures-details.md#3-two-things-the-compute-shader-must-do-that-the-vertex-stages-do-not)
5. **Have `Classify` ask the two records directly, not an upstream exclusion it does not own.** Instance flag for "does this surface deform", geometry flag for "is this stream the deformed one"; `ResidentCounters::AnimatedInstancesRefused` makes a refusal visible. [Details](deformed-surfaces-in-acceleration-structures-details.md#4-ask-the-two-records-not-an-exclusion-someone-else-owns)
6. **Read opacity from the material, not the returned `GeometryClass`.** An alpha-masked character is both `Masked` and `Deformed` and `MostRestrictive` returns `Deformed`, which would force hair cards and leaves opaque. Derive each consumer's answer from the property it depends on. [Details](deformed-surfaces-in-acceleration-structures-details.md#5-one-geometryclass-slot-two-independent-properties)
7. **Stage the geometry record against the deformed buffer so the key is per-surface.** The key is `(vertex buffer, index buffer, submesh)`; two characters sharing a skinned asset share the rest buffer and would share a BLAS despite different poses. The deformed stream must stay byte-for-byte an `OloEngine::Vertex` array (else `OLO_RT_VERTEX_STRIDE` becomes per-geometry); BLAS build, hit-triangle fetch and alpha confirmation all follow `GPUSceneGeometry::VertexAddress`. The raster path is untouched and the cache is never enabled on OpenGL. [Details](deformed-surfaces-in-acceleration-structures-details.md#6-the-geometry-key-moves-with-the-stream-and-that-is-what-gives-per-instance-structures)
8. **Do not drive refits from `FingerprintGeometry` or the skeleton's deformation revision.** The fingerprint hashes addresses, counts and formats (deformation moves none); #1226 advances bone history every frame for every skinned entity, so a still fox got a refit every frame and a full rebuild every eighth. [Details](deformed-surfaces-in-acceleration-structures-details.md#7-a-pose-change-is-invisible-to-a-geometry-fingerprint)
9. **Let the producer answer "did the data change".** `DeformedSurfaceCache` hashes the bone palette bytes (not floats, no epsilon) and advances `DeformedContentRevision` only when it dispatches; the lane rides the instance record in the former `DeformationPad0`. Idle should read `dispatched=0, skipped=1, refits=0, builds=0`. A frame counter cannot answer a question about data. [Details](deformed-surfaces-in-acceleration-structures-details.md#7-a-pose-change-is-invisible-to-a-geometry-fingerprint)
10. **In `DecideBuild`, test the pose (`deformationAdvanced`) before the refit-budget heuristic, ignore it on a first build, and record the revision only when a build was recorded.** Reversed order rebuilds a still character every frame; `HasDeformation` separates "built at revision 0" from "never built"; unconditional storage leaves a skipped or failed surface stuck on an old pose. [Details](deformed-surfaces-in-acceleration-structures-details.md#7-a-pose-change-is-invisible-to-a-geometry-fingerprint)
11. **Order producer and consumer explicitly and emit the barrier from the producer.** `RayTracingScenePass` calls `DependsOnPass("SkeletalDeformPass")` (do not rely on adjacent `AddNode`); the barrier is compute write to AS build read, destination access `SHADER_READ`, not `ACCELERATION_STRUCTURE_READ`. [Details](deformed-surfaces-in-acceleration-structures-details.md#8-the-producer-writes-the-consumer-builds-and-the-barrier-is-the-producers)
12. **Do not add a counter you never write.** `BlasBuildGpuNs` / `TlasBuildGpuNs` (#978) read zero forever and were removed in #1337. Bracket GPU work with `GPUPassTimerPool::BeginSubPass("SkeletalDeformToBuffer")` and read `AccelerationStructureBuild` in `olo_perf_pass_timings`. [Details](deformed-surfaces-in-acceleration-structures-details.md#9-do-not-add-a-counter-you-never-write)
