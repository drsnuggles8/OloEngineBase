# Vulkan: a CPU buffer write between two recorded draws is a semantic, not a memcpy

Rules for any CPU write (`SetData`/`Upload`) to a buffer that Vulkan draws or dispatches read. GL runs buffer writes and draws in command order; a write-through Vulkan buffer does not (postmortem of #691, #1052, #1058, #1080, #1171, #1351).

## Rules

1. **Audit every `SetData`/`Upload` site for "same buffer written more than once per frame with draws recorded between the writes".** Each such site needs per-write versioning (arena snapshot, ring, or per-draw allocation). A persistent write-through buffer cannot express it, and the failure is silent: no error, no validation message, no dropped-draw counter. [Details](vulkan-command-ordered-buffer-writes-details.md#the-rule)
2. **Ask which side produces the data before versioning a buffer.** Arena snapshots are correct only for CPU-produced data. `PushSnapshot` refuses `StorageBufferUsage::DynamicCopy` and `StreamCommandOrdered`. A CPU `SetData` on a GPU-output buffer leaves draws reading a stale snapshot while compute writes the persistent buffer. [Details](vulkan-command-ordered-buffer-writes-details.md#the-mirror-image-failure-snapshotting-a-buffer-the-gpu-produces-1052--1058)
3. **Keep the draw/compute address split.** Draws read `GetRootDataAddress()` (the snapshot when live); compute dispatches read `GetDeviceAddress()` (always persistent, `commandOrderedBufferReads=false` in `AssembleAndPushRootData`). Compute SSBOs are GPU-write participants. Take no snapshot outside a recording bracket. [Details](vulkan-command-ordered-buffer-writes-details.md#the-fix-adr-0011-amendment-80)
4. **A snapshot covers the whole buffer, or there is no snapshot (#1080).** `PushSnapshot` sizes every snapshot to `m_Size`; when it cannot source the unwritten bytes it refuses, warns once and increments `VulkanStorageBuffer::GetSnapshotRefusedCount()`. `GetRootDataAddress()` carries no length, so a short snapshot leaves shader indexing as the only bound. Compare snapshot size against buffer size when auditing. [Details](vulkan-command-ordered-buffer-writes-details.md#the-mirror-image-failure-snapshotting-a-buffer-the-gpu-produces-1052--1058)
5. **Use `ClearData()` / `ClearData(offset, size)` for resets, never a CPU `SetData` of zeros.** A clear stays in the GPU command stream on both backends and so orders against recorded dispatches. Any CPU write to a buffer a compute dispatch reads is suspect once more than one happens per frame (`GPUParticleSystem::Compact()` counters, #1171). Use per-write versioning when the write is real data. [Details](vulkan-command-ordered-buffer-writes-details.md#and-again-in-the-gpu-particle-counters-1171)
6. **Do not publish a probe through a buffer the pipeline rewrites each frame.** It reads back the last writer's bytes, not the probe's. [Details](vulkan-command-ordered-buffer-writes-details.md#and-again-in-the-gpu-particle-counters-1171)
7. **Treat vertex-pull streams as mutable after the first `SetData`.** After construction, the first `SetData` makes a vertex-pull stream mutable; every later pull draw uses an arena snapshot. A first rewrite after a persistent draw recorded this frame is refused; a partial first rewrite of a staged buffer with unreadable tail is refused. Streams over half an arena slot use command-ordered transfers (#1446). [Details](vulkan-command-ordered-buffer-writes-details.md#current-buffer-family-audit-1351)
8. **When fixing a failure class in one buffer type, check the other types sharing the shape.** Vertex buffers kept write-through for two years after UBOs and SSBOs were fixed (#1171). A comment saying "nothing does X" ages into a bug. [Details](vulkan-command-ordered-buffer-writes-details.md#the-same-hole-left-open-in-vertex-buffers-for-two-years-1171)
9. **Give a CPU-written compute input a new allocation or a recorded transfer.** Compute inputs get a fresh published allocation per version (retired through deferred reclaim), or `UploadBufferSubData` / `RenderCommand::BindTransientStorage` ranges (#1543). The audit table lists each family (GPU Scene tables, cull inputs, terrain picker, VSM, foliage, particle and fluid staging, RT tables, groom surfaces). [Details](vulkan-command-ordered-buffer-writes-details.md#current-buffer-family-audit-1351)
10. **Never take a draw snapshot for a buffer only dispatches read.** A partial `SetData` on a mapped `DynamicDraw` buffer inside a recording reads the rest back from write-combined memory (tens of MB/s); that was the 3 ms fluid emit cost (#1543). The one-time warning "filled N unwritten bytes by reading write-combined mapped memory" names such a site. [Details](vulkan-command-ordered-buffer-writes-details.md#current-buffer-family-audit-1351)
11. **A delayed-read test must prove the next version was written before it checks the old one survived.** Otherwise it passes a revert vacuously. Delayed-read tenants exist for GPU Scene, palette, BLAS, foliage and fluid (#1526); shadow and cull consumers remain #1538. [Details](vulkan-command-ordered-buffer-writes-details.md#current-buffer-family-audit-1351)
12. **Pin interleaving with a tenant that interleaves two uploads of one buffer between draws.** `VulkanPassSuite.InterleavedInstanceBufferUploadsKeepCommandOrderAcrossDraws` is the model (upload LEFT, draw, upload RIGHT, draw). A suite that never interleaves stays green. [Details](vulkan-command-ordered-buffer-writes-details.md#the-fix-adr-0011-amendment-80)
13. **Localize "backend X renders scene Y wrong but scene Z right" with the three-step checklist.** Pinned-pose screenshots on both backends, `olo_render_capture_target` on `SceneDepth` to separate geometry from post, then survivor-pattern reasoning. A bug keyed on how content is submitted (batched vs unique meshes) looks like a content bug. [Details](vulkan-command-ordered-buffer-writes-details.md#how-it-was-localized-the-method-is-the-lesson)
14. **A/B one build apart before blaming a fix for a fault it revealed.** Removing a large mapped stand-in made a never-run consumer run for the first time. [Details](vulkan-command-ordered-buffer-writes-details.md#the-mirror-image-failure-snapshotting-a-buffer-the-gpu-produces-1052--1058)
