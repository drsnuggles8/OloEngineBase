# Steamworks platform integration

Read before touching anything under `OloEngine/src/Platform/Steam/`, the `OLO_WITH_STEAM` CMake plumbing, or the Steam Lua bindings. Governing fact: the Steamworks SDK cannot exist in this public repository and cannot reach CI (Valve login, no redistribution licence); every rule follows from it (#644).

## Rules

1. **Allow exactly one TU to include a Valve header: `Platform/Steam/SteamworksBackend.cpp`.** Everything else talks to `ISteamBackend` (`SteamBackend.h`). This keeps logic fake-testable, the stub SDK sufficient, and the `OLO_WITH_STEAM=0` link surface unchanged. Enforced by the `single-valve-tu` job in `.github/workflows/steam-stub.yml`. [Details](steamworks-platform-integration-details.md#4-exactly-one-tu-may-include-a-valve-header)
2. **Include the SDK as `#include "public/steam/steam_api.h"` and root the include dir at the SDK's `sdk` directory, never `.../public`.** Valve ships `isteamnetworkingutils.h` and others under the same names as GameNetworkingSockets, so a `steam/` child on the include path hijacks Networking headers (twelve C2365 errors inside a Steamworks header). The stub SDK mirrors the `public/steam/` layout. [Details](steamworks-platform-integration-details.md#but-the-sdk-will-hijack-gnss-headers-engine-wide-if-you-put-it-on-the-include-path)
3. **Write the single-TU guard against `public/steam/`, anchored to `^\s*#include`, and test the mixed case.** GNS also includes `<steam/steamnetworkingsockets.h>`, so a plain `steam/` grep flags the netcode. Add a second check that the Steam TUs never use a bare `steam/` form. A file with both a GNS and a Steamworks include must fail. Do not touch `Networking/` while working on Steamworks. [Details](steamworks-platform-integration-details.md#4-exactly-one-tu-may-include-a-valve-header)
4. **Resolve the SDK from `STEAMWORKS_SDK_ROOT` (the inner `sdk` directory containing `public/` and `redistributable_bin/`); never vendor it, add a vcpkg entry or an overlay port.** Vulkan is the precedent, not Mono. [Details](steamworks-platform-integration-details.md#1-it-is-a-developer-installed-sdk-not-a-vendored-one--vulkan-is-the-precedent-not-mono)
5. **Define `OLO_WITH_STEAM` PUBLIC on `OloEngine` in both the ON (`=1`) and OFF (`=0`) branches.** [Details](steamworks-platform-integration-details.md#1-it-is-a-developer-installed-sdk-not-a-vendored-one--vulkan-is-the-precedent-not-mono)
6. **Warn loudly when `STEAMWORKS_SDK_ROOT` is set but invalid; stay silent when it is unset.** A variable pointing one level too high (outer folder, no `public/steam`) must produce the corrected path in native separators, not a silent OFF default. Any option that auto-detects from the environment needs distinct outcomes for "configured but wrong" and "not configured". [Details](steamworks-platform-integration-details.md#2-auto-detecting-the-sdk-has-a-silent-failure-mode-and-it-is-the-likeliest-user-error)
7. **Call `olo_copy_steam_runtime()` (`cmake/CommonProperties.cmake`) from all four executable scopes: `OloEditor`, `OloRuntime`, `OloServer`, `OloEngine-Tests`.** `steam_api64.lib` is an import library, so every executable has a static import of `steam_api64.dll`; a missing DLL shows a bare load dialog with no log line. The CRT-triplet mismatch does not apply to the import stub. [Details](steamworks-platform-integration-details.md#3-every-executable-needs-steam_api64dll--including-the-ones-that-never-call-steam)
8. **Keep both degradation variants.** Compile time: `OLO_WITH_STEAM=0` makes `CreateSteamBackend()` return `NullSteamBackend` (the complete no-op set; no second stub class). Run time: `SteamAPI_InitEx()` failure warns with an actionable sentence, sets availability false and returns. [Details](steamworks-platform-integration-details.md#5-two-degradation-variants-and-they-are-not-interchangeable)
9. **Never throw on Steam init failure.** `Application`'s `AudioEngine::Init()` / `NetworkManager::Init()` throw branches are the counter-example; "no Steam client" is an ordinary state. Protect it with a test. [Details](steamworks-platform-integration-details.md#5-two-degradation-variants-and-they-are-not-interchangeable)
10. **Keep both fakes.** `FakeSteamBackend` (`tests/Platform/Steam/`) drives engine logic with no Valve type; the stub SDK (`src/Platform/Steam/StubSDK/`) lets the one Valve-calling TU compile, link and run in CI. If the stub job fails on a missing call, add the declaration to `StubSDK/public/steam/steam_api.h` and the canned implementation to `StubSDK/SteamStubSDK.cpp`; do not delete the job. [Details](steamworks-platform-integration-details.md#6-two-fakes-at-two-levels-and-they-are-not-redundant)
11. **Do not copy the CI stub-build flags (`-DOLO_WITH_USD=OFF -DOLO_WITH_ALEMBIC=OFF -DOLO_WITH_MATERIALX=OFF`) into a Windows configure, and do not trust a Windows stub-build recipe.** They are verified on `x64-linux` only; Windows fails at link with unresolved `google::protobuf` externals from `GameNetworkingSockets_s.lib` (not Steam). If you retry: fresh build directory, explicit options, unset `STEAMWORKS_SDK_ROOT` in the environment. Cheap check that works: `cl /Zs` on the stub TUs. [Details](steamworks-platform-integration-details.md#reproducing-the-stub-build-locally-on-windows--do-not-copy-the-ci-flags)
12. **Use the Steamworks API forms that fail visibly.** `SteamAPI_InitEx` (not `SteamAPI_Init`); the overlay toast fires on `StoreStats()`, but dedup first (`UnlockAchievement` returns `AlreadySet` without storing); `GetAchievement()` false means an unknown id, so log loudly; read overlay display state from `GameOverlayActivated_t`, not `IsOverlayEnabled()`; use `CCallbackManual` with `Register()` in `Initialize()` / `Unregister()` in `Shutdown()`; check both `IsCloudEnabledForAccount()` and `IsCloudEnabledForApp()`; report a zero-length cloud file as `NotFound`. [Details](steamworks-platform-integration-details.md#7-steamworks-api-details-that-are-easy-to-get-wrong)
13. **Call `SteamManager::Shutdown()` unconditionally from both teardown sites in `Core/Application.cpp` (the constructor `catch (...)` and the destructor).** Pump `SteamAPI_RunCallbacks` in `Run()` after the input/platform block and before `ProcessTasks`, never in `RenderFrameLayers` (re-entrancy latch pumps twice). [Details](steamworks-platform-integration-details.md#8-initshutdown-pairs-across-two-shutdown-sites)
14. **Keep Steam a static process-level manager (`SteamManager`), not an ECS component.** That avoids the cross-binding touch-point set in CLAUDE.md. [Details](steamworks-platform-integration-details.md#9-it-is-a-process-level-service-not-an-ecs-component)
15. **State the three verification tiers in any Steam PR, and never report Steam features working from OFF-path or stub tests.** Tiers: CI every push (OFF path plus stub ON path via `steam-stub.yml`); one machine only (real SDK, App ID 480 via `OloEditor/steam_appid.txt`, which is git-ignored and must be removed for a release build); not verified (Vulkan overlay). [Details](steamworks-platform-integration-details.md#10-what-can-and-cannot-be-verified-and-how-to-say-so)
16. **Let Steam Input govern the physical controller when `SteamManager::IsInputAvailable()` and a controller is connected; never OR it with engine gamepad polling.** In `InputActionManager::Update()` activate the action set named `InputContextTypeToString` of the active context, skip `GamepadButton`/`GamepadAxis` bindings and query the Steam action named `InputAction::Name`; `Active == false` skips the Steam contribution. Keyboard and mouse are never affected. Callers never call `Input*` lifecycle methods; only `IsInputAvailable()` and the query methods. [Details](steamworks-platform-integration-details.md#the-decision-steam-input-wins-when-available-per-gamepad-origin-binding)
17. **Know the Steam Input limits: first controller only, one axis (`X`) per action, Trigger-mode normalized once in `SteamworksBackend::GetAnalogActionState`.** An action missing from the manifest is unreachable by design (add it to the manifest, no special case). The stub proves plumbing, not manifest correctness. Leaderboards, DLC and UGC are non-goals. [Details](steamworks-platform-integration-details.md#the-surface)
18. **Record real-SDK Steam Input rows 2, 3, 4 and 6 as blocked, not passed, until a project-owned App ID has a manifest.** App 480 has no manifest for this project. [Details](steamworks-platform-integration-details.md#manual-real-sdk-verification-checklist-tier-2-from-10)
