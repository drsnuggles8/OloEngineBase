# Script-driven structural registry changes need a deferred command queue

Issue #643 (`Scene::ScriptCreateEntity` / `ScriptInstantiatePrefab` / `ScriptDestroyEntity`). Read this before exposing any new script binding that creates or destroys an entity, adds or removes a component, or reparents a hierarchy.

## Rules

1. **Never apply a structural registry change inline from a script; queue a command.** The queue lives on `Scene` (`m_PendingEntityCommands` plus two pending-UUID sets, mutex-guarded) and is applied by `Scene::FlushPendingEntityCommands()` at the top and bottom of `Scene::UpdateScripts`. [Details](script-structural-command-safe-point-details.md#the-rule)
2. **Do not reason "game thread, so inline is safe".** The hazard is iterator invalidation, not threads: `UpdateScripts` walks `view<ScriptComponent>()` / `view<LuaScriptComponent>()` while dispatching `OnUpdate`, and spawn or destroy mutates that pool. A script destroying its own entity is a use-after-free in `OnUpdateEntity`. [Details](script-structural-command-safe-point-details.md#why-inline-is-wrong-even-though-scripts-run-on-the-game-thread)
3. **Always defer; do not add a scope that defers only inside `UpdateScripts`.** Script callbacks also come from dialogue actions, UI button handlers, `GameplayEventBus` subscribers and GOAP callbacks, mostly mid-iteration, so one uniform contract is the only one a new call site cannot break. [Details](script-structural-command-safe-point-details.md#why-always-defer-and-not-defer-only-inside-updatescripts)
4. **Keep both drains (leading and trailing).** The trailing drain makes a spawn visible to physics, `PropagateTransforms` and rendering in the same tick; the leading drain bounds latency for requests queued from the other call sites to one tick. [Details](script-structural-command-safe-point-details.md#why-the-drains-bracket-the-script-loops-two-calls-not-one)
5. **A deferred spawn returns a pre-allocated UUID, and the spawn transform is an argument.** Use `Instantiate(handle, pos, rot, scale)`; writing `e.Translation` after `Instantiate(h)` writes to nothing. [Details](script-structural-command-safe-point-details.md#the-api-shape-this-forces-and-why-it-is-the-right-shape-anyway)
6. **`Entity.IsValid` reports the logical answer** (`Scene::IsEntityLiveForScripts`): true for a pending spawn, false from the moment a destroy is requested. [Details](script-structural-command-safe-point-details.md#the-api-shape-this-forces-and-why-it-is-the-right-shape-anyway)
7. **Destroy is idempotent.** Gate on `m_PendingDestroyIDs.insert(...).second` so two `Destroy` calls queue one command. [Details](script-structural-command-safe-point-details.md#the-api-shape-this-forces-and-why-it-is-the-right-shape-anyway)
8. **Do not read components of an unresolvable handle.** `ScriptGlue.cpp`'s `GetEntity(UUID)` (used by the generated `OLO_PROPERTY` bindings) resolves through `Scene::GetEntityByUUID`, which asserts in Debug and uses `FindChecked` in Release for an unknown UUID. Guards must use `Entity_HasComponent`, Lua `entity_utils.get_component` / `has_component`, which resolve via `TryGetEntityWithUUID`. API docs state that a spawned entity's components are unreadable until the next tick. [Details](script-structural-command-safe-point-details.md#known-sharp-edge-component-access-on-an-unresolvable-handle)
9. **Drain in rounds, with a re-entrancy flag and a round cap.** Swap the queue, apply the batch, repeat; a nested `Flush` is a no-op; `kMaxEntityCommandDrainRounds` is per `Flush`, not per tick, so two budgets per tick. Read and write the flag under the queue's mutex. [Details](script-structural-command-safe-point-details.md#other-invariants-that-bit-during-implementation)
10. **Apply a batch in request order.** Spawn-then-destroy in one tick runs `OnCreate` then `OnDestroy` on a live entity. [Details](script-structural-command-safe-point-details.md#other-invariants-that-bit-during-implementation)
11. **Script destroy goes through `Scene::DestroyEntityAndChildren`,** not `Scene::DestroyEntity`, which does not recurse (children first, then unlink the root from its parent). Otherwise spawn/despawn loops leak one entity per prefab child per cycle. [Details](script-structural-command-safe-point-details.md#other-invariants-that-bit-during-implementation)
12. **The drain fires `OnCreate` for the whole spawned subtree.** The `OnRuntimeStart` sweep covers only entities that existed at session start; Lua registers an instance only on a successful `OnCreate`. [Details](script-structural-command-safe-point-details.md#other-invariants-that-bit-during-implementation)
13. **The Lua `OnCreate` path falls back to `LuaScriptComponent::ScriptFile` verbatim with no project mounted,** because `Project::GetAssetFileSystemPath` asserts without an active project. [Details](script-structural-command-safe-point-details.md#other-invariants-that-bit-during-implementation)
14. **Clear the queue at `OnRuntimeStart` and `OnRuntimeStop`.** Leftover commands name entities of a scene that no longer exists. [Details](script-structural-command-safe-point-details.md#other-invariants-that-bit-during-implementation)
15. **Before marking the `Scripts` node `.Parallelizable()`, move the drains to a barrier node.** The request side is worker-safe; the apply side does EnTT structural changes and is game-thread-only. See the "EnTT + worker threads: first-touch is a WRITE" note in `CLAUDE.md`. [Details](script-structural-command-safe-point-details.md#if-you-ever-mark-the-scripts-node-parallelizable)
16. **Keep `SOL_ALL_INTEGER_VALUES_FIT=1` as a PUBLIC compile definition on `OloEngine`.** Lua's `lua_Integer` is signed 64-bit, so a `u64` UUID above `INT64_MAX` throws "integer value will be misrepresented in lua" under `SOL_ALL_SAFETIES_ON`. It is set in CMake, not per TU, for the same ODR reason as `ENTT_USE_ATOMIC`. [Details](script-structural-command-safe-point-details.md#the-lua-u64-trap-this-uncovered-sol_all_integer_values_fit)
17. **Emit big ids spliced into Lua source as signed decimals,** `std::to_string(static_cast<i64>(handle))`; an unsigned decimal literal above `INT64_MAX` lexes as a float and fails sol2's check. See `LuaIdLiteral` in the Functional test. A Lua script printing such an id sees a negative number. [Details](script-structural-command-safe-point-details.md#the-lua-u64-trap-this-uncovered-sol_all_integer_values_fit)

## Where the contract is pinned

- `OloEngine/tests/Functional/Scripting/LuaSpawnsAndDestroysEntitiesTest.cpp`: deferral, UUID stability, prefab hierarchy, `OnCreate`, self-destroy, 30-tick churn under both the parallel and `OLO_GAMEPLAY_SCHEDULER_SEQUENTIAL=1` executors.
- `OloEngine/tests/Lua/LuaBindingTest.cpp`: binding existence and queue-level semantics.
