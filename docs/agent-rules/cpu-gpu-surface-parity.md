# A surface two subsystems must agree on, and the three ways they agree on the wrong thing

Rules for any case where a shader displaces geometry that gameplay code must also sample (a deforming terrain, a soft-body surface, a heightfield the AI paths over). Written from issue #968 (Drift's Kelvin wake); foam field: [persistent-world-space-fields.md](persistent-world-space-fields.md).
Applies to: `OloEngine/src/OloEngine/Renderer/Water/WaterWake.h`, `WaterWakeSystem.{h,cpp}`, `OloEditor/assets/shaders/include/WaterWakeCommon.glsl`, `OloEngine/src/OloEngine/Physics3D/WaterProbe.cpp`.

## Rules

1. **Do not make one subsystem the only place a shared value exists.** A GPU-written raster cannot be parity-tested (readback stall, frame of lag). Make the shape an analytic function of a small record built once per tick (four hulls, eight poses, 80 `vec4` = 1280 B in `WaterUBO`) that both the shader (`WaterWakeCommon.glsl`) and `WaterProbe::SampleSurfaceY` -> `WaterWake::Evaluate` evaluate; `WaterWakeParityTest` then asserts parity. [Details](cpu-gpu-surface-parity-details.md#1-a-raster-cannot-be-parity-tested-choose-the-representation-for-that)
2. **Pin the input space of a CPU/GPU mirror, not only its arithmetic.** Gerstner/FFT choppiness moves a vertex horizontally, so evaluate at the displaced vertex's absolute world XZ (`vec2 wakeXZ = displacedPos.xz + u_RenderOrigin.xz;`), matching `WaterSurface::SampleHeight`'s column space. State the space at the top of the shared header; a same-point parity test cannot check it. The footprint-suppression circularity is second order; note it, do not iterate it. [Details](cpu-gpu-surface-parity-details.md#2-the-two-halves-can-agree-on-the-function-and-disagree-about-where)
3. **Test the production GLSL, not a copy.** `ShaderUnit_WaterWake.glsl` `#include`s `WaterWakeCommon.glsl`, which takes its records through a hook (`vec4 waterWakeFetch(int index);`) defined over `u_WakeHulls[]` in the water stages and over an SSBO in the probe. Give a function a seam instead of the test a copy (`ShaderUnit_Fog.glsl` duplicates verbatim and passes when the two drift). [Details](cpu-gpu-surface-parity-details.md#3-a-probe-shader-that-copies-the-production-glsl-tests-the-copy)
4. **When a physical constant is a ratio, make the test vary the denominator.** The Kelvin half-angle is `asin(1/3) = 19.47 deg`, speed-independent: `offset(age) = halfBeam + tan(19.47 deg) * |speed| * age`. A lateral velocity (#967's `1.6 m/s * age`) narrows the wake as the boat accelerates; `WaterWakeShapeTest.ArmRidgeSitsAtTheKelvinHalfAngleAndIsSpeedIndependent` sweeps 4, 8 and 16 m/s. [Details](cpu-gpu-surface-parity-details.md#4-the-kelvin-half-angle-is-a-ratio-and-a-spread-rate-is-speed-dependent)
5. **Lay two consumers of one pose history from the same poses, ages and offset function.** Foam arms and height ridge share one loop through `BoatWakeSystem::ArmOffset` (delegating to `WaterWake::ArmOffset`); otherwise foam lands beside the ridge. The arm-splat budget per boat went 6 to 14 against the field's 96-splat cap. [Details](cpu-gpu-surface-parity-details.md#5-two-consumers-of-one-pose-history-must-sample-the-same-poses)
6. **Frame an evidence subject, do not pose the camera.** Use `EditorCamera::Focus(point, distance, yaw, pitch)` rather than `SetPose(eye, yaw, pitch)`, whose yaw convention errors produce a plausible frame of the wrong place (four of five #968 captures pointed away from the boat). [Details](cpu-gpu-surface-parity-details.md#5b-a-hand-posed-evidence-camera-photographs-whatever-it-is-pointed-at)
7. **Assert the A/B difference for a change-driven subject.** "The wake changes the frame" with `maxDiff = 0` caught what a rebased golden RMSE cannot. A probe whose value is identical in both A/B halves tells you nothing. [Details](cpu-gpu-surface-parity-details.md#5b-a-hand-posed-evidence-camera-photographs-whatever-it-is-pointed-at)
8. **Bisect CPU to pixels by making each intermediate visible in turn.** Is the uniform arriving (`displacedPos.y += u_WakeShapeParams.y * 2.0`), does the array read (`u_WakeHulls[2].z`), does the hook work, does the evaluator fire at a fixed point inside the wake, does it fire at the vertex's own position. [Details](cpu-gpu-surface-parity-details.md#5b-a-hand-posed-evidence-camera-photographs-whatever-it-is-pointed-at)
9. **Put a gameplay switch where a headless tick publishes it.** The visual-only wake mode lives on `WaterProbe::Volume`, read from the `WaterComponent`, not on `WaterWakeSettings`, which `Scene::ProcessScene3DSharedLogic` publishes on the render path only; a switch a headless tick cannot open is a feature no headless test can cover. [Details](cpu-gpu-surface-parity-details.md#6-where-the-switches-live-decides-whether-the-tests-can-see-them)
10. **Check the build log, not the wrapper's exit code.** `build-lock.ps1` returned 0 for a build with 15 `static_assert` errors; grep the log for `error:` and check the `[n/total]` progress line. The `WaterUBO` size is pinned twice: `WaterRenderingTest` and the assert in `ShaderBindingLayout.h`. [Details](cpu-gpu-surface-parity-details.md#7-the-build-wrappers-exit-code-is-not-the-builds-exit-code)
