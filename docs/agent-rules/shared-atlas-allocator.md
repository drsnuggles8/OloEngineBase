# Shared atlas allocator (#718) — what it is, what it isn't, and a non-RAII leak trap

`OloEngine::AtlasAllocator` (`Renderer/AtlasAllocator.h`) is a reusable power-of-two square-region allocator (a fixed quadtree in a flat 4-ary heap: node 0 is the whole atlas, children of node `i` at `4i+1..4i+4`). Read before adding a consumer, touching `ShadowAtlas::PersistentAllocator`, `ImpostorBaker`, or `FoliageRenderer`'s layer storage.

## Rules

1. **Measure before calling `Allocate()` on a hot path.** It is a plain O(nodes-at-that-level) linear scan, cheap only because neither current consumer allocates per frame (shadow repack on rank/tier change, impostor bake on mesh/params change). The shadow atlas table is in the low thousands of nodes; the impostor budget (8192px atlas / 32px min tile) has about 87k, about 65k at the finest level. [Details](shared-atlas-allocator-details.md#shared-atlas-allocator-718--what-it-is-what-it-isnt-and-a-non-raii-leak-trap)
2. **Leave `ShadowAtlas::Allocate()` (the free function) unchanged.** `ShadowAtlasPackingTest.cpp` asserts sizes, ranks, counts, overlap and determinism but not tile coordinates. Production code (`Scene.cpp` shadow setup) calls `ShadowMap::AllocateAtlasTiles()`, which forwards to a `ShadowAtlas::PersistentAllocator` owning an `AtlasAllocator` across frames. [Details](shared-atlas-allocator-details.md#shadowatlas-the-free-function-is-untouched-production-code-moved-to-a-new-stateful-sibling)
3. **Identify casters across frames by `Candidate::UserData` as a `u64`.** It is the light entity's UUID; a truncated `u32` would alias lights into reusing each other's tiles, and `UserData == 0` is always treated as new. [Details](shared-atlas-allocator-details.md#shadowatlas-the-free-function-is-untouched-production-code-moved-to-a-new-stateful-sibling)
4. **Keep the ranking/tiering/budget loop duplicated in `PersistentAllocator::Allocate`.** The two backends fail placement at different points (shelf-packer exhaustion vs buddy fragmentation), entangling "which rank got which size" with "did placement succeed". [Details](shared-atlas-allocator-details.md#shadowatlas-the-free-function-is-untouched-production-code-moved-to-a-new-stateful-sibling)
5. **Know the one-call lag.** A departed caster, and one whose rank crossed a tier boundary, are freed eagerly; a still-candidate caster that is out-ranked or over budget frees on the trailing sweep and is available next call. Near capacity this can reject a candidate the old shelf packer would place; it is deliberate (generous atlas headroom), and a fix would be a two-pass solver. [Details](shared-atlas-allocator-details.md#shadowatlas-the-free-function-is-untouched-production-code-moved-to-a-new-stateful-sibling)
6. **Use swap-not-mutate for identity-keyed free-on-drop.** Swap `m_Live` into a local `previousLive` at the top, build the new `m_Live` from this call's accepted set (removing reused slots from `previousLive`), and free the remainder at the end. Do not iterate the live set and free what is not kept. [Details](shared-atlas-allocator-details.md#shadowatlas-the-free-function-is-untouched-production-code-moved-to-a-new-stateful-sibling)
7. **Keep the impostor atlas a VRAM budget, not spatial packing.** `ImpostorBaker` owns a static process-wide `AtlasAllocator` for accounting; `Bake()` reserves a power-of-two region before creating GPU textures and on exhaustion logs and returns an invalid atlas (which `FoliageRenderer` already skips). Spatial sharing would need a scissored shared framebuffer, a UV scale/offset in `Foliage_Impostor.glsl`, and a rewrite of `ImpostorBakeEvidenceTest.cpp`'s `ConeBakesViewDependentOctahedralAtlas` (which assumes the atlas width/height is this bake's footprint). See [foliage-impostor-card-rendering.md](foliage-impostor-card-rendering.md). [Details](shared-atlas-allocator-details.md#impostor-atlas-a-vram-budget-deliberately-not-spatial-packing)
8. **Use those three risks as the checklist for any consumer that wants placement.** The terrain virtual texture (#715) places its adaptive variable-size virtual images with the same allocator. [Details](shared-atlas-allocator-details.md#impostor-atlas-a-vram-budget-deliberately-not-spatial-packing)
9. **Free `ImpostorAtlas.BudgetNode` explicitly at every discard site.** It is a plain `u32` handle, not `Ref<T>`, so `vector::resize()` shrinking `FoliageRenderer::m_Layers` leaks the claim for the process lifetime. Call `ImpostorBaker::Free(atlas)` at the two `data.Impostor = ImpostorAtlas{}` resets, the rebake overwrite, the layer-count shrink before `m_Layers.resize()`, and `FoliageRenderer`'s own destructor. [Details](shared-atlas-allocator-details.md#the-vectorresize-non-raii-leak-trap)
10. **Do not give `ImpostorAtlas` a destructor.** A user-declared destructor suppresses the implicit move operations, so `data.Impostor = ImpostorBaker::Bake(...)` would copy-assign and double-free the new `BudgetNode`. `AtlasAllocator::Free` tolerates a double-free as a documented no-op, which makes the mistake survivable but not correct. [Details](shared-atlas-allocator-details.md#the-vectorresize-non-raii-leak-trap)
11. **Grep every discard site of a value type that embeds a plain accounting handle.** `= T{}`, `vector::resize()`, `vector::erase()` and the enclosing destructor, not only the ones that felt like removal. [Details](shared-atlas-allocator-details.md#the-vectorresize-non-raii-leak-trap)
