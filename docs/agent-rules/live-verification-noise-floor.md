# Verifying a diagnostic against a live scene: measure the noise floor first

Distilled from the issue #607 region-capture slice. Applies when you verify a read-back tool or a visual capture against a running scene, write a multi-pose capture test, or see modified PNGs under `OloEditor/assets/tests/visual/` after a test run.

## Rules

1. **Measure the noise floor before attributing any difference.** Capture the same thing twice, compare, and report that number with the finding. If the floor is comparable to the signal the run is INCONCLUSIVE: say so and exit non-zero-but-distinct, never PASS. Two captures of the same 96x64 `SceneColor` rect differed by up to 185/255 per channel (FFT water, temporal accumulation, auto-exposure). [Details](live-verification-noise-floor-details.md#the-trap)
2. **Include a control that must fail.** Compare against the position a broken implementation would produce (the mirrored row range scored 70 against 166 for the correct one, so the check proved nothing). Same rule as in [render-graph-transient-aliasing.md](render-graph-transient-aliasing.md). [Details](live-verification-noise-floor-details.md#the-rules)
3. **Pin coordinate and format math deterministically.** Upload a synthetic texture whose value encodes its coordinates (`R = x/(W-1)`, `G = y/(H-1)`, y top-down), read it back through the real path, assert per texel (`OloEngine/tests/Rendering/CaptureRegionReadbackTest.cpp`). Pick the probe rect off-centre and off-axis, or a vertical mirror cancels out. [Details](live-verification-noise-floor-details.md#the-rules)
4. **Use live verification for wiring questions, not math.** It answers "is it wired up, does it see real data" (it found an empty transient-pool acquire order because `TransientPool::ReleaseAll()` empties the lists at frame end and every MCP read marshals at a frame boundary). [Details](live-verification-noise-floor-details.md#the-rules)
5. **Make every multi-pose capture test call both guards in `OloEngine/tests/Rendering/PropertyTests/VisualEvidenceGuards.h`:** `ExpectCapturesAreDistinct` (every pair differs by more than a multiple of the measured floor) and `ExpectFrameHasSubject` (a content mask finds the subject). Test the guards with a control: `MeshVisibilityEvidenceTest` feeds one pose captured twice and requires failure. Issue #931: `EditorCamera::SetPosition`/`SetYaw`/`SetPitch` never rebuilt the view matrix, so three "angles" were one frame. [Details](live-verification-noise-floor-details.md#the-same-rule-inside-a-capture-test)
6. **Do not commit or debug PNG diffs that a rerun of the same binary produces.** `OloEngine-Tests.exe` rewrites many evidence PNGs under `OloEditor/assets/tests/visual/` every run (`WorldOriginRebase_rebased_after` moves 4.43% of pixels, max channel 111; `Fluid_*` 0.26–0.53%). [Details](live-verification-noise-floor-details.md#the-suites-own-evidence-pngs-are-nondeterministic--measured-values)
7. **Tell evidence from goldens.** A test that writes unconditionally produces evidence (noise when modified). A test that writes only under `--olo-golden-rebase` (`Water_*`, `Drift_*`, `MeshVisibility_*`, siblings) produces a golden that a normal run compares; a modified golden means you passed `--olo-golden-rebase`. [Details](live-verification-noise-floor-details.md#the-suites-own-evidence-pngs-are-nondeterministic--measured-values)
8. **Decide noise with three snapshots:** `HEAD` (`git show HEAD:<path>`), run 1, and a second run of the same binary. If `HEAD->run1` is not clearly larger than `run1->run2` it is noise; then `git checkout --` the directory. [Details](live-verification-noise-floor-details.md#the-suites-own-evidence-pngs-are-nondeterministic--measured-values)
9. **Compare an intermediate target against itself, not an `olo_screenshot`.** The screenshot is `UIComposite` (post-fog, post-tonemap, viewport resolution); `SceneColor` is pre-fog HDR clamped to [0,1] and may differ in render scale (1411x942 vs 941x628). [Details](live-verification-noise-floor-details.md#corollary-intermediate-targets-do-not-look-like-the-frame)
10. **Check the editor is running frames before interpreting anything.** A minimized editor skips `EditorLayer::OnUpdate` (`Application::Run` guards on `!m_Minimized`) but `MarshalRead` still answers, so every read tool returns plausible stale data. Look for read and refresh paths gated by different conditions. [Details](live-verification-noise-floor-details.md#corollary-check-the-editor-is-running-frames-before-you-interpret-anything)
11. **Use the liveness signals.** `olo_perf_snapshot` has a `liveness` block (`ticking`, `frameIndex`, `msSinceLastFrame`, `iconified`, `focused`) that separates stalled from slow; `olo_screenshot` sets `stale: true`, emits a leading `STALE FRAME:` block and reports `frameIndex` (same index means same frame); `olo_input_inject` refuses up front; `driver.ps1 -Action attach` un-minimizes the editor. `focused` gates nothing; only iconify or a stalled clock stops things. [Details](live-verification-noise-floor-details.md#corollary-check-the-editor-is-running-frames-before-you-interpret-anything)
