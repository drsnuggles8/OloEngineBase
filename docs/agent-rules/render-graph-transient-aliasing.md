# Render-graph transient aliasing: version renames, stale pool reads, and how to hunt them

Rules for `RGBuilder::WriteNewVersion`, the transient planner, temporal history sinks, and hunting one-frame garbage or black squares that appear on camera moves (VehiclesTest water scene, issue #438 follow-up; #902). Two independent mechanisms (a `WriteNewVersion` orphan allocation and NaN amplification in bloom) produced near-identical symptoms; when a repro survives a fix that closed one mechanism, re-measure from scratch.

## Rules

1. **Treat `RGBuilder::WriteNewVersion(handle, usage, tag)` as a rename of the same physical resource, never an allocation.** A versioned name (`SceneColor@GPUDrivenOcclusionPass`) resolves via `RenderGraph::m_VersionAliasTargets` (`ResolveTexture` / `ResolveFramebuffer` / `ResolveBuffer` follow it through the direct by-name maps, not `Get*Handle`); `RenderGraphTransientPlanner::ComputePlan` skips it (`SkipReason = "version-alias"`) and folds its accesses into the source's lifetime; `MaterializeTransientResources` does no pool acquire for it. Pinned by `RenderGraphVersionAlias.*` in `RenderGraphTest.cpp`. A rename does not license sampling an attachment while writing it (render-graph-attachment-feedback.md). [Details](render-graph-transient-aliasing-details.md#the-contract-writenewversion-is-a-rename-never-an-allocation)
2. **For any new mechanism that mints a derived resource name (views, versions, MSAA resolves, mip views), decide explicitly: rename (register a resolution alias, never allocate) or real allocation (planner entry).** Getting it wrong is invisible until a plan rebuild reshuffles the pool, not a crash. [Details](render-graph-transient-aliasing-details.md#review-checklist-for-new-graph-features)
3. **Make any consumer that reads a transient outside the pass schedule visible to the planner.** `FlushExtractions` runs after every pass, so a history source with accesses in one pass was freed and overwritten (#902); `RenderGraphTransientPlanner::PlanInput::IsExtractedAfterExecution` extends such a source to the last pass. Pinned by `RenderGraphTransientPool.HistoryExtractionSourceOutlivesItsLastPassAccess`. A readback, cross-frame copy or async-compute reader is the same bug. [Details](render-graph-transient-aliasing-details.md#a-resource-read-after-the-last-pass-needs-its-lifetime-said-out-loud)
4. **Set `OLO_RG_DISABLE_ALIASING=1` the moment a temporal or multi-pass feature "runs but does nothing".** With per-resource backing, accumulation worked instantly (SSGI temporal resolve: 0.3% better aliased, 10.8x better fixed). [Details](render-graph-transient-aliasing-details.md#a-resource-read-after-the-last-pass-needs-its-lifetime-said-out-loud)
5. **Set `OLO_RG_POISON_TRANSIENTS=1` to make a stale-pool read a deterministic every-frame signal.** It clears every pool-acquired transient to a per-resource hue and logs `RG poison map: <resource> -> <color>`, so the colour names the leaking resource. Launch via the driver so the env reaches the editor: `$env:OLO_RG_POISON_TRANSIENTS='1'; driver.ps1 -Action attach`. [Details](render-graph-transient-aliasing-details.md#the-instruments-permanent-env-gated)
6. **Do not use per-pass toggle bisection for stale-name bugs.** Publication/latest-maps outlive the pass that created the version (render-pass-published-state.md), so disabling it does not stop consumers resolving a stale name; ten single-pass sweeps came back negative. [Details](render-graph-transient-aliasing-details.md#the-bug-archetype-this-guards-against)
7. **Suspect pool aging when a repro rate grows over a session.** High-watermark frames leave extra objects per bucket (`Trim` keeps `maxPerBucket`), giving more reshuffle candidates; LIFO pool stability otherwise hands an orphan last frame's real texture, so "is this target clean?" captures are fooled. [Details](render-graph-transient-aliasing-details.md#the-bug-archetype-this-guards-against)
8. **Never hold a `Ref` to a pool object across `ReleaseAll()` as ownership.** The pool hands the same object to the next acquirer regardless of refcount; keep cross-frame state in renderer-owned storage (the `RegisterHistoryTextureSink` / `ImportHistory` copy pattern TAA uses). [Details](render-graph-transient-aliasing-details.md#review-checklist-for-new-graph-features)
9. **Remember an unqualified `Get*Handle` name redirects to the latest version; the dependency you record traces to that version's producer.** [Details](render-graph-transient-aliasing-details.md#review-checklist-for-new-graph-features)
10. **Verify an A/B lever acted before trusting an exoneration.** `olo_render_toggle_pass` takes lowercase feature names (`gtao`, `taa`, `fog`, `bloom`, `fxaa`, `godrays`, ...), not pass node names; "Unknown pass" errors swallowed by a script fabricated ten exonerations. Read and assert on every tool response, require a lever-consistent frame change, and restore state by writing back the previous reported value, not an unconditional off-then-on. [Details](render-graph-transient-aliasing-details.md#verify-every-instrument-before-trusting-an-exoneration)
11. **Check existing tools before building a hunt.** `olo_render_graph_topology_export` carries resolved physical GL ids per pass access; `olo_render_validate` reports versioned-name physical-id groups (a version whose physical differs from its base is this bug). [Details](render-graph-transient-aliasing-details.md#hunt-protocol-what-actually-worked-in-order)
12. **Do not trust a by-name capture of a resource as clean.** It may resolve a stale physical and be a one-frame-old copy; use poison mode, then hue-coded poison, then read the declaration site named by the `@tag`. [Details](render-graph-transient-aliasing-details.md#hunt-protocol-what-actually-worked-in-order)
13. **Guard every fragment-stage `normalize()` of an interpolated or summed vector with `safeNormalize(v, fallback)`.** `Water.glsl` emitted one NaN pixel on ~10% of camera-jump frames; the `len2 > 1e-12` predicate is false for NaN too. Also zero-length-guard the VS/TES FFT-derivative normalizes. [Details](render-graph-transient-aliasing-details.md#nan-amplification-one-bad-pixel-becomes-a-300-px-black-square)
14. **Keep the non-finite kill at the end of `PostProcess_BloomDownsample.glsl` as a ternary select, not `mix()`.** `mix(NaN, 0, 1)` is still NaN. Bloom spread 3 NaN channels into 367,074 (a ~303x303 px black block), and the NaN also washed out auto-exposure. [Details](render-graph-transient-aliasing-details.md#nan-amplification-one-bad-pixel-becomes-a-300-px-black-square)
15. **Hunt NaN origins with `OLO_RG_BLACKSQUARE_HUNT=1` and census NaNs per channel, not black blocks.** It reads back after every pass and logs `BLACKSQUARE HUNT NAN: after pass 'X' …`; the first pass logged is the origin. Heavy: hunts only. Capture mid-chain resources at a pinned time (`afterPass:`), since end-of-frame captures show the legal reuser's content. [Details](render-graph-transient-aliasing-details.md#nan-amplification-one-bad-pixel-becomes-a-300-px-black-square)
