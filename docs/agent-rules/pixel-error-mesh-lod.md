# Pixel-error mesh LOD (generation + selection)

The classic-mesh LOD path: `Renderer/LOD.{h,cpp}` for selection, `MeshOptimization::BuildAutoLODChain` / `GenerateAutoLODGroup` for generation (issue #711). Read before touching LOD selection, generation, `LODGroupComponent` serialization or ownership of generated level meshes.

## Rules

1. **Make `EstimateProjectedPixelSize` depend on camera position, FOV and render height only; never project the AABB through the view-projection.** Screen-position dependence makes levels flip as the camera sways and gives garbage for off-screen/behind-camera shadow casters. Pin with `LODGroup.PixelSizeIsInvariantToCameraOrbit` and `AutoMeshLODScene.LODOrbitDoesNotSwitchLevels`, orbiting a single subject at the orbit centre so distance stays fixed (value tests of `SelectLODByPixelError` cannot tell the implementations apart). [Details](pixel-error-mesh-lod-details.md#1-the-projection-plane-faces-the-mesh-not-the-camera--and-the-wrong-one-passes-every-test)
2. **Take per-axis extent as `length(modelMatrix[i]) * localSize[i]`; never re-fit an AABB around a rotated one.** A refit grows by up to sqrt(3) and pumps the level as the object spins (`LODGroup.PixelSizeIsInvariantToObjectRotation`). [Details](pixel-error-mesh-lod-details.md#1-the-projection-plane-faces-the-mesh-not-the-camera--and-the-wrong-one-passes-every-test)
3. **Express meshoptimizer attribute weights in normalized-position units: normal weight = `importance * (averageVertexDistance / modelExtent)`.** `meshopt_simplify*` rescales positions to unit extent and returns a relative error; a raw model-space distance gives a different chain for centimetre vs metre authoring and fails silently. [Details](pixel-error-mesh-lod-details.md#2-the-error-is-a-ratio-and-meshoptimizer-is-why)
4. **Discriminate scale-invariance on accumulated error and index buffers, not triangle counts.** With `target_error = FLT_MAX` counts match under any weighting. Keep `MeshOptimization.AutoLODChainIsInvariantToModelScale` (same chain length, triangles within 2%, errors within 10%) paired with `MeshOptimization.NormalWeightMustBeNormalizedByModelExtent` (asserts the error band is missed and index buffers differ). [Details](pixel-error-mesh-lod-details.md#2-the-error-is-a-ratio-and-meshoptimizer-is-why)
5. **Recompute the average vertex distance from the level being simplified; do not estimate it as `sqrt(2)^level`.** A topology-limited step breaks the estimate. [Details](pixel-error-mesh-lod-details.md#2-the-error-is-a-ratio-and-meshoptimizer-is-why)
6. **Keep both selection paths and switch on `HasErrorData()`.** Any level with `Error > 0` selects by pixel error; none (hand-authored and pre-#711 data) keeps legacy `MaxDistance` thresholds. `Error` defaulting to 0 must stay meaningful ("no measurement"); do not use a -1 sentinel. Generated `MaxDistance` values are nominal (1080p / 90 degrees reference). [Details](pixel-error-mesh-lod-details.md#3-two-selection-paths-coexist-and-haserrordata-is-the-switch)
7. **Update all four places when touching `LODLevel::Error` (`LODGroupComponent` is in `kComponentsCustomSerialize`).** `Scene/SceneSerializer.cpp` (emit and read with `std::isfinite`); `SaveGame/SaveGameComponentSerializer.cpp::SerializeLODLevel` (layout change bumps `kSaveGameFormatVersion`, see binary-format-versioning.md); `LODLevel::operator==` bitwise (cpp-coding-quality.md §2a, else inspector edits cannot be undone); the mirror in `OloEngine/tests/Serialization/NestedStructSerializerCodegenTest.cpp`. [Details](pixel-error-mesh-lod-details.md#4-lodlevelerror-is-a-serialized-field-in-four-places)
8. **Never persist a generated chain level by level; treat a group as derived if `m_AutoGenerated` is set OR any level is a memory-only asset.** Memory-only handles are dead next process (cache-stored-unresolvable-reference.md; shows only on the second load). Neither check alone is enough: the flag survives released assets, the handle check catches a half-edited chain. [Details](pixel-error-mesh-lod-details.md#4a-a-generated-chain-is-derived-data-and-is-not-persisted-level-by-level)
9. **Touch `m_AutoGenerated` only in the two actions that change where a level's geometry came from.** Generate LODs sets it; re-pointing a level at a real asset clears it; distance drags, adds and removes do not. It carries `OLO_SERIALIZE(Skip)` so the MCP writable-field registry does not expose it. [Details](pixel-error-mesh-lod-details.md#4a-a-generated-chain-is-derived-data-and-is-not-persisted-level-by-level)
10. **When regeneration declines, still add the component empty with `Enabled`, `Bias` and the marker.** Reasons: auto-LOD off, no graphics device, no asset manager, mesh the simplifier cannot reduce. An empty group is inert (`SelectLODMesh` returns early). [Details](pixel-error-mesh-lod-details.md#4a-a-generated-chain-is-derived-data-and-is-not-persisted-level-by-level)
11. **Save-games write zero levels for a derived group and keep the live levels on load.** `Serialize(FArchive&, LODGroupComponent&)` does this so stale handles do not clobber the chain the scene load rebuilt. [Details](pixel-error-mesh-lod-details.md#4a-a-generated-chain-is-derived-data-and-is-not-persisted-level-by-level)
12. **Guard every `AssetManager::IsMemoryAsset` call with `Project::HasAssetManager()`.** It asserts without an asset manager. [Details](pixel-error-mesh-lod-details.md#4a-a-generated-chain-is-derived-data-and-is-not-persisted-level-by-level)
13. **Release generated level meshes in `Scene::OnComponentRemoved<LODGroupComponent>` via `ModelImporter::ReleaseGeneratedLODAssets`, and keep `LODGroupComponent` in `kComponentsCustomOnRemove` (`tools/OloHeaderTool/main.cpp`) and `ComponentHandlerCoverageTest`'s mirror in sync.** It frees only handles in `m_GeneratedLODHandles` that are still memory-only. [Details](pixel-error-mesh-lod-details.md#4b-the-generated-meshes-have-an-owner-and-it-is-oncomponentremoved)
14. **Release the chain explicitly in `Scene::DestroyEntity`.** `OnComponentRemoved` is called by hand from `Entity::RemoveComponent<T>`, not an entt signal, so `m_Registry.destroy()` never fires it (grep `m_Registry.destroy() does NOT fire` in `Scene.cpp` for the other members). [Details](pixel-error-mesh-lod-details.md#4b-the-generated-meshes-have-an-owner-and-it-is-oncomponentremoved)
15. **Run `ModelImporter::DiscardGeneratedLODGroup` before the eligibility gate, never inside it.** Re-importing assigns a new `m_MeshSource` onto an existing entity, so the old chain is stale even if generation then declines; an authored group is never discarded. Pinned by `ModelImporterTest.StaticToAnimatedReimportDiscardsTheGeneratedLODGroup`. [Details](pixel-error-mesh-lod-details.md#4b-the-generated-meshes-have-an-owner-and-it-is-oncomponentremoved)
16. **Do not copy `m_GeneratedLODHandles` in the copy constructor.** Ownership is not duplicable; a duplicated entity degrades to full detail when the original is deleted (known residual; the fix is the shared per-mesh chain cache). [Details](pixel-error-mesh-lod-details.md#4b-the-generated-meshes-have-an-owner-and-it-is-oncomponentremoved)
17. **Stop `SelectLODByPixelError`'s scan at any level whose `Error` is not finite and positive.** The inspector's "Add LOD Level" appends `Error = 0`, which satisfies every budget and would be chosen at every distance. [Details](pixel-error-mesh-lod-details.md#4c-a-zero-error-level-past-index-0-is-unmeasured-not-free)
18. **Remember the limits: multi-submesh sources are rejected (everything collapses to material 0), shadow casters always draw LOD 0 (`SubmitMeshSourceClassic`), and there is no cross-entity chain sharing.** Skinned and morph sources were enabled by #1227 (`MeshOptimization::CopyDeformationStreams`, `Scene::SelectAnimatedSurfaceLOD`; see morph-and-lod-in-the-animated-surface.md). [Details](pixel-error-mesh-lod-details.md#5-what-this-does-not-cover)
19. **Skip auto-generation at import when `AutoLODImportConfig::RequireGraphicsDevice` is set (default) and `RenderCommand::IsDeviceAvailable()` is false.** A test wanting the chain without a device clears the flag. Never touch an entity that already has a `LODGroupComponent`, and drop the group when the chain is LOD 0 alone. [Details](pixel-error-mesh-lod-details.md#6-auto-generation-at-import-is-guarded-on-the-graphics-device)
