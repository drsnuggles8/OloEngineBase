# Generated evidence stays out of Git

**Commit what a test reads, never what a test writes.** A golden or fixture that a test loads and
compares against is source: it is tracked and listed in
[`scripts/generated-evidence-allowlist.txt`](../../scripts/generated-evidence-allowlist.txt) with
the test that reads it. A capture, report, replay scene, timing ledger or log that a run produces is
output: it stays in the ignored directory the test wrote it to, and the PR body cites its file name
and the measurement taken from it. Issue #1610.

## The rules

1. **Output directories are ignored as a whole.** Every file in `OloEditor/assets/tests/visual/`,
   `exports/` and `memory/`, and every non-Markdown file under `docs/testing/evidence/`, is in
   `.gitignore`; the directories themselves are not, so `git add` on a tracked golden still succeeds.
   A new evidence test needs no ignore rule of its own. Do not add per-campaign globs.
2. **A golden is force-added and allow-listed.** After `--olo-golden-rebase` writes a new golden,
   `git add -f` it and add one allow-list line: the glob, then the suite that reads it. A golden that
   moves because of a deliberate visual change is an ordinary modification of a tracked file and needs
   nothing new.
3. **The `generated-evidence` pre-commit hook enforces both lists.** It rejects any file under
   `OloEditor/assets/tests/` that the allow-list does not name, any non-Markdown file under `docs/` that
   it does not name, and any tracked file anywhere that the repository's `.gitignore` files exclude (a
   force-add; a developer's global excludes file is not consulted).
   It also rejects an allow-list line with no reader and a line that no longer allows any file that needs
   it. Its negative
   controls run first on every invocation.
4. **A curated documentation image is linked from a doc.** Keep a review image only when a page
   embeds or links it. Put it under `docs/images/<topic>/`, or keep it beside the write-up in
   `docs/testing/evidence/<campaign>/` with `git add -f` and an allow-list line naming the page. Never
   commit a whole campaign so that a write-up can say "the raw files are in this directory".
5. **The write-up keeps the numbers.** A campaign's Markdown summary records every measurement a reader
   needs. Raw output that a reader might want later is regenerated by the command the summary names, or
   is retrieved from history with `git show <sha>:<path>`. A CI job that produces evidence uploads it as
   an artifact with bounded retention.
6. **Classify by reader, not by directory.** Goldens and evidence share `visual/`, and a file name
   says nothing about which one it is. A file is a golden only if a test loads it and fails without it.
   Prove that by running the reading suites with the file absent, never by its name.

## Why

By 2026-10 the tracked tree was 2.19 GB. `visual/` held 2,656 files (974 MB), of which 189 were goldens
that some test reads. `docs/testing/evidence/` held 610 files (300 MB), most of them unlinked raw
campaign output. Every evidence test rewrote its tracked PNG on each run, so a full-suite sweep left
about 300 modified files to discard (#1300), and a commit that kept them added another full copy of each to
history. A fresh clone of `master` was 3.25 GiB. Packing everything reachable from `master` gives
3.26 GiB, and 1.08 GiB without the blobs that ever lived in these output locations and are not a
current golden or curated file.

Deleting such a file later shrinks the tree, not the clone: the old blobs stay reachable from every
commit that had them. The per-campaign ignore globs that #1524, #1553 and #1593 added each caught one
campaign after it had already been committed once, and the next campaign used new names.

The task loop's old rule made the problem structural. It required the proof of an artefact-backed
verification cell to be "a committed file named after the cell". That rule now asks for the file name
and its measurement in the PR body instead (see
[task-loop.md §2a](../process/task-loop.md#2a-the-verification-matrix--run-every-cell-or-give-a-fact-for-the-one-you-didnt)).

## How the golden set was found

Static reading was not enough. Golden paths are built at run time (`"Water_" + poseName + ".png"`),
and one name can be a golden in one test case and an evidence write in another. The golden set was
measured instead. With every file in `visual/` moved aside, the reading suites were run in compare
mode, including `--olo-golden-vendor=amd`. Each `Missing golden` failure named a file that a test
reads. Those files were restored and the suites were re-run until no read failed. The result is the
allow-list, and every entry names its suite. A test that writes a missing golden instead of failing,
or compares only when the file exists, would hide from this method. Every failing case reported its
missing file, and no reader gates its comparison on the file existing.

## History

The cleanup in #1610 untracked the outputs and did not rewrite history. The measured savings, the
affected refs and the migration steps for a rewrite are in
