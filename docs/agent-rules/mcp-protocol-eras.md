# MCP protocol eras — why the stateless core is deferred, and what shipped instead

Spec `2026-07-28` splits MCP into a legacy era (`2025-11-25` and earlier, `initialize` handshake) and a modern stateless era. Evidence behind issue #777's decision to not advertise `2026-07-28` yet. Read before touching `OloEditor/src/MCP/McpServer.cpp`'s version list, `HandleInitialize`, `HandleGetStream`, or `McpClient.cpp`'s connect sequence. Scope from the normative spec (`schema.ts`, Versioning and Compatibility, Streamable HTTP), not the blog announcement.

## Rules

1. **Do not add `2026-07-28` to `kSupportedProtocolVersions` until the whole modern set works.** It requires `server/discover`, per-request `_meta` (`io.modelcontextprotocol/protocolVersion` and `/clientCapabilities` required), `Mcp-Method` + `Mcp-Name` header validation, errors `-32020` / `-32021` / `-32022` with mandated data and HTTP status, 404 for method-not-found, removal of the GET SSE stream (`GET`/`DELETE` answer 405), `subscriptions/listen`, cancellation by closing the response stream, ignoring `Mcp-Session-Id` and `Last-Event-ID`, `logging/setLevel` folded into `_meta`, MRTR, and `resultType` on every result. It is a second transport shape, not a field addition. [Details](mcp-protocol-eras-details.md#1-what-advertising-2026-07-28-actually-costs)
2. **Do not ship `server/discover` alone.** A modern client treats a `DiscoverResult` as proof of a modern server; answering it from a server that still needs `initialize`, mints session ids and serves a GET stream turns a working legacy fallback into a broken modern conversation. Ship it with `_meta`, `resultType`, routing headers, the three error codes and GET-stream removal, or not at all. [Details](mcp-protocol-eras-details.md#3-the-trap-serverdiscover-cannot-be-added-on-its-own)
3. **Revisit on a trigger, not a date.** Triggers: a client we use sends `2026-07-28` requests (`_meta`-carrying POSTs, or a 400/405 to a modern probe); a bridged external server goes modern-only (the server half needs rework); MCP SDK Tier-1 servers drop the legacy handshake. [Details](mcp-protocol-eras-details.md#5-when-to-revisit)
4. **Build the migration as one additive route.** Serve `server/discover`, `_meta`, routing headers, `resultType` and `subscriptions/listen` alongside the existing handshake, leave the legacy path untouched and tested, and advertise the new version only once the set works. The load-bearing test is the legacy path still passing. [Details](mcp-protocol-eras-details.md#5-when-to-revisit)
5. **Keep `McpClientConnection::NegotiateEra`'s order.** Probe `server/discover` with a modern `_meta`; a `DiscoverResult` or `-32022` means modern (a recognized modern error triggers a version retry, never a fallback); anything else, including no reply, is legacy and the `initialize` / `notifications/initialized` handshake runs unchanged. [Details](mcp-protocol-eras-details.md#4a-the-outbound-client-is-dual-era)
6. **Stamp `_meta` in `SendRequest`, the single funnel, in the modern era.** Version, `clientInfo` and an empty per-request `clientCapabilities`; a server must not infer capabilities from an earlier call. [Details](mcp-protocol-eras-details.md#4a-the-outbound-client-is-dual-era)
7. **Keep the probe timeout separate and short.** `McpClientConfig::DiscoverProbeTimeout` is 3 s, clamped to `HandshakeTimeout`, so a legacy child that swallows unknown methods does not cost every connect the full handshake timeout. A late probe response is harmless (the pending entry is erased). [Details](mcp-protocol-eras-details.md#4a-the-outbound-client-is-dual-era)
8. **Refuse `resultType != "complete"` loudly.** An absent `resultType` means `"complete"`; an interim `input_required` (MRTR) result must return a tool error, never be forwarded to the agent as the answer. [Details](mcp-protocol-eras-details.md#4a-the-outbound-client-is-dual-era)
9. **Leave `logging` and the `notifications/message` push unchanged.** Dropping them early breaks every `2025-*` client, which is all of them. The offramp carrier is `notifications/resources/updated` on the subscribable resource `olo://events/recent` (200 newest events plus `lastId`, byte-identical to `olo_events_tail`), with `resources/subscribe` / `resources/unsubscribe` and `capabilities.resources.subscribe: true`; the same notification works in both eras and `SubscriptionFilter` is a closed set of four types. [Details](mcp-protocol-eras-details.md#4b-the-logging-offramp-has-a-carrier-and-both-run-side-by-side)
10. **Make only resources with a `ResourceDef::ChangeToken` subscribable.** Without a cheap monotonic token a subscription promises updates that never arrive; `resources/subscribe` rejects others with `-32602` naming the URIs that work. [Details](mcp-protocol-eras-details.md#4b-the-logging-offramp-has-a-carrier-and-both-run-side-by-side)
11. **Capture the baseline token at subscribe time in `HandleResourcesSubscribe`, not on the first poll.** Seeding at first poll swallows changes landing before the stream opens. A repeated subscribe keeps the baseline; unsubscribing erases it so a resubscribe re-baselines. [Details](mcp-protocol-eras-details.md#4b-the-logging-offramp-has-a-carrier-and-both-run-side-by-side)
12. **Do not build a per-session subscription registry now.** The set is server-global because the GET stream carries no session identity; it over-delivers, and it dissolves under `subscriptions/listen`. [Details](mcp-protocol-eras-details.md#4b-the-logging-offramp-has-a-carrier-and-both-run-side-by-side)
13. **Remember why staying legacy is acceptable.** A localhost diagnostics server with one client gets none of the stateless-core benefits, a botched dual-era transport endangers the instrument used to verify other work, removals have a 12-month-plus offramp, and the spec rates dual-era client against legacy server as Works. [Details](mcp-protocol-eras-details.md#2-why-it-is-a-no-go-now)
