# Assembling a server-authoritative multiplayer loop

Rules from issue #636, which found ~20 well-tested networking classes and a working transport that had never been assembled into a running loop. Read before touching `OloEngine/src/OloEngine/Networking/`, and especially before adding "one more networking class".

## Rules

1. **Grep for callers of a subsystem's drive function (`Tick`, `Update`, `Poll`, `Flush`) before reading anything else.** Zero callers means the subsystem is decorative however green its tests are. Fix any stale "X drives Y" comment in the same change. [Details](server-authoritative-networking-loop-details.md#1-how-a-fully-tested-subsystem-produces-nothing)
2. **Test the assembled loop, not only primitives.** The Functional-axis test stands up a real server and two real clients; unit tests call the primitive directly, which is the call site production lacked. [Details](server-authoritative-networking-loop-details.md#1-how-a-fully-tested-subsystem-produces-nothing)
3. **Run all replication on the game thread.** Snapshot capture, apply, spawn/despawn and RPC handlers touch the EnTT registry. `NetworkThread` owns only `RunCallbacks()` and named-thread tasks; `NetworkManager::Tick(dt)` does polling, replication, entity lifecycle, RPC handlers and interpolation. `s_Mutex` guards only `s_Server`, `s_Client`, `s_ActiveScene`, `s_Initialized`; `Tick()` copies the pointers and releases the lock before scene work. [Details](server-authoritative-networking-loop-details.md#2-replication-runs-on-the-game-thread-all-of-it)
4. **Route connection events through a queue.** The transport only records transitions (`NetworkServer::DrainClientEvents`); the replication tick drains them on the game thread. Record only the first `Connected` delivery or you spawn a second pawn. [Details](server-authoritative-networking-loop-details.md#the-consequence-people-miss-connection-events)
5. **Give the client its own input counter.** Stamp inputs with `ClientReplicationDriver::m_InputTick`, monotonic from 1, never the server's replication tick (the server drops `tick <= lastProcessed`, so only the first input works). [Details](server-authoritative-networking-loop-details.md#31-the-clients-input-tick-must-be-the-clients-own-counter)
6. **Apply an input locally when you record it.** `ClientPrediction::RecordInput` only buffers; without a local apply the pawn waits a round trip. [Details](server-authoritative-networking-loop-details.md#32-recording-an-input-is-not-predicting-it)
7. **Reconcile by snapping owned entities to the newest authoritative state, then replaying unacknowledged inputs.** `SnapshotInterpolator` skips predicted entities, so they never receive authoritative state otherwise. [Details](server-authoritative-networking-loop-details.md#33-reconciliation-must-rewind-before-it-replays)
8. **Interpolate by ownership, not authority.** Skip an entity only if non-server authority and `OwnerClientID == myLocalClientID`; the server assigns the client id in a `Connect` message. Every pawn is client-authoritative, so an authority test freezes remote players. [Details](server-authoritative-networking-loop-details.md#34-interpolate-by-ownership-not-by-authority)
9. **Delta against the last acknowledged snapshot.** The client acks the newest applied tick (`SnapshotAck`); the server keeps un-acked snapshots per connection (bounded to 32) and sends a full resend past that. The client must reassemble deltas into full state before handing them to the interpolator. [Details](server-authoritative-networking-loop-details.md#35-a-delta-baseline-must-be-an-acknowledged-baseline)
10. **Dispatch message handlers outside the transport's lock, always.** `NetworkClient::PollMessages` held `m_Mutex` across dispatch and self-deadlocked on the first reply. Near-zero CPU over a long wall-clock is a blocked process. [Details](server-authoritative-networking-loop-details.md#36-a-transport-that-dispatches-inside-its-own-lock-deadlocks-every-handler-that-replies)
11. **Do not take the lock inside a lock-holding iterator callback.** `NetworkServer::ForEachConnection` holds `m_Mutex` and `GetClientPingMs` takes it; prefer returning a snapshot (`GetConnectionSnapshot()`). When adding the first caller to a dormant API, assume its other call sites never ran: grep and read them. [Details](server-authoritative-networking-loop-details.md#the-same-shape-again-an-iterator-that-holds-the-lock)
12. **Make input commands exact displacements, and validate on the server.** Reconciliation replay has no timeline, so a "move at speed s" command never converges. Bake the step on the client (`NetworkMovementInput`); the server clamps step length. [Details](server-authoritative-networking-loop-details.md#4-input-commands-must-be-displacements-not-direction--speed)
13. **Build loop objects that take `Scene` and transport as parameters.** `ServerReplicationDriver` and `ClientReplicationDriver` do, because `NetworkManager` is a static singleton and a two-client test is impossible in one process. Ask "what would a two-client test look like?" first. [Details](server-authoritative-networking-loop-details.md#5-make-the-loop-objects-not-more-statics-on-the-facade)
14. **Filter and sort interest results.** `NetworkInterestManager::GetRelevantEntities` covers non-networked entities, so filter to replicated ones; sort the set, because the baseline is compared as bytes. [Details](server-authoritative-networking-loop-details.md#6-scoping-identity-and-lifecycle-details-worth-writing-down)
15. **Despawn only what the client's spawn path created (`m_LocallySpawned`).** Scene-file entities must not be deleted when they leave relevance. [Details](server-authoritative-networking-loop-details.md#6-scoping-identity-and-lifecycle-details-worth-writing-down)
16. **Carry initial state in the spawn payload.** Reuse the snapshot record as the payload's tail. Snapshot apply must not materialise missing components; spawn must (`InterpolationEntry::Ensure`, the `ensureComponents` flag on `EntitySnapshot::ApplyEntityRecord`). [Details](server-authoritative-networking-loop-details.md#6-scoping-identity-and-lifecycle-details-worth-writing-down)
17. **Frame snapshots as `[serverTick: u32][snapshot bytes]`.** This time-bases interpolation and rejects out-of-order arrivals without changing the format `EntitySnapshot::Parse` reads. [Details](server-authoritative-networking-loop-details.md#6-scoping-identity-and-lifecycle-details-worth-writing-down)
18. **Rewind lag compensation by half-RTT plus the client's render delay, and keep the history unscoped.** The server's assumed render delay must match `SnapshotInterpolator::SetRenderDelay`. [Details](server-authoritative-networking-loop-details.md#6-scoping-identity-and-lifecycle-details-worth-writing-down)
19. **Resolve RPCs through the local `RpcRegistry` and check authority at both ends.** The wire carries a name hash only; the receiver's re-check against the arrival direction is the one that matters. Registry lookups return a copy, not a pointer. [Details](server-authoritative-networking-loop-details.md#7-rpc-the-registry-is-the-authority-boundary)
20. **Key RPC direction and ownership checks off `senderClientID == 0`, not `receivedOnServer`.** `0` means the server originated the call; otherwise the server cannot act on client-owned pawns and a Multicast skips the host. When funnelling a path into the shared `ExecuteLocally`, re-read its preconditions; assert recipient count (3: two clients plus the server). [Details](server-authoritative-networking-loop-details.md#received-on-the-server-is-not-the-same-as-sent-by-a-client)
21. **Apply `RequiresOwnership` to entity-bound server RPCs**, with an opt-out for legitimate non-owner calls. Mark script-registered handlers `ScriptOwned` and drop them from `LuaScriptEngine::Shutdown` and `ScriptEngine::ShutdownMono` / `ReloadAssembly`, or they outlive their VM and crash. [Details](server-authoritative-networking-loop-details.md#received-on-the-server-is-not-the-same-as-sent-by-a-client)
22. **Hosts must register the scene and tick after simulation.** Call `NetworkManager::SetActiveScene(scene)` at runtime-scene start and `SetActiveScene(nullptr)` before release; call `NetworkManager::Tick(ts)` once per frame after the simulation step. Hosts: `OloServerApp`, `OloRuntimeApp`, `EditorLayer::StartActiveRuntimeScene` / `OnSceneStop`. Never register `m_EditorScene`. [Details](server-authoritative-networking-loop-details.md#8-the-host-contract)
23. **A live scene swap clears scene-derived state, never connection-derived state.** Clear acked baselines, known sets, history, spawned-archetype map, queued spawns/despawns and observer positions; keep the `ClientState` entry, tick clock and per-client input ticks. `ResetForSceneSwap` is the scene-swap half; `Reset()` is for server stop. `NetworkManager::SetActiveScene` sets a flag the next `Tick` acts on (not a retained `Scene*`, which can compare equal to a new allocation). [Details](server-authoritative-networking-loop-details.md#a-live-scene-swap-is-not-a-restart--do-not-clear-per-connection-state)
24. **Keep the server tick monotonic across a swap and send despawns before clearing `Known`.** Pinned by `ServerAuthoritativeLoopTest.ALiveSceneSwapKeepsReplicatingToStillConnectedClients`; only a client connected across the swap can observe the bug. [Details](server-authoritative-networking-loop-details.md#a-live-scene-swap-is-not-a-restart--do-not-clear-per-connection-state)
