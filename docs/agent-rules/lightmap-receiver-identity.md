# A baked lightmap region is addressed by `(entity UUID, sub-key)` — never by the entity alone

Issue #867 extended baked GI (#439) past the classic `MeshComponent`. Read before touching `Scene/SceneLightmapGather.*`, `LightmapEntityEntry`, `SceneLightmapRuntime`, the instanced draw path, or `Model::DrawParallel`.

## Rules

1. **Key every region by `(EntityUUID, SubKey)`.** `SubKey == 0` means the whole entity. `MeshComponent` and `VirtualMeshComponent`: 0 (one component is one `MeshSource`). `InstancedMeshComponent`: the instance's `InstanceData::StableID`, with `AssetStableIDNamespace` ORed in for placement-asset instances. `ModelComponent`: the index of the FIRST `Model::GetMeshes()` entry sharing that mesh's `MeshSource` (on the warm `.omesh` path the whole model is one unwrap and one region). [Details](lightmap-receiver-identity-details.md#the-rules)
2. **Gather receivers through `GatherLightmapReceivers`, never your own walk.** The editor bake gather, the reference world, the runtime's re-unwrap and `ComputeBakeKey` all read one list; a mismatch renders with no baked GI and no error (cf. issue #629). [Details](lightmap-receiver-identity-details.md#the-rules)
3. **Include the sub-key in the packing sort's tie-break.** `LightmapBaker::Prepare` orders plans by (size desc, UUID asc, SubKey asc); without it `std::sort` may order one batch's instances differently between runs and the bit-identical-bake contract is lost. [Details](lightmap-receiver-identity-details.md#the-rules)
4. **Use a persistent, not positional, per-instance identity.** `StableID` means insert/erase does not re-key later instances; the save-game format round-trips `StableID` from v26 instead of re-deriving it in `EnsureStableIDs`. [Details](lightmap-receiver-identity-details.md#the-rules)
5. **Build the bake's reference world with `AddLightmapReceivers`, not `ReferenceSceneBuilder::AddScene`.** `AddScene` walks `MeshComponent` only, so instanced static geometry would be missing as occluders and bounce. [Details](lightmap-receiver-identity-details.md#the-rules)
6. **Write the instanced region into the buffer the draw reads.** That is `imc.Instances` on the inline-only fast path and `imc._MergedCache.Data` otherwise; stamp it with `SceneLightmapRuntime::GetResolveGeneration()` and zero the stamp on anything that invalidates the merge. [Details](lightmap-receiver-identity-details.md#the-rules)
7. **Expect a `ModelComponent` bounce colour from its `MeshSource` (known approximation).** The bake uses `ResolveSubmeshMaterial(override, MeshSource, submesh, default)`; a cold Assimp import whose per-mesh sources lack imported materials bakes with the engine default (less saturated bounce, never a wrong atlas address). The fix is threading `Model::m_Materials` into `ReferenceSceneBuilder`. [Details](lightmap-receiver-identity-details.md#known-approximation-a-models-bounce-colour-comes-from-its-meshsource)
8. **Prefer uniform scale on lightmap-static batches.** `ReferenceSceneBuilder::AddMeshEntity` shares a mesh only for uniformly scaled, positively oriented transforms; others get a full vertex copy, so bake peak memory scales with instance count (a cost, not a wrong result). [Details](lightmap-receiver-identity-details.md#known-cost-a-non-uniformly-scaled-instance-duplicates-its-geometry-in-the-bake)
9. **Wire a per-draw value through a `FrameDataBuffer` stream when it survives auto-batching.** `Renderer3D::DrawMeshInstanced` patched back only Colors, Customs and EntityIDs, leaving `DrawMeshInstancedCommand::lightmapRegionBufferOffset` at `UINT32_MAX` so every instanced draw read the zero sentinel; a lane wired at both ends but not the middle looks unwired. [Details](lightmap-receiver-identity-details.md#the-plumbing-hop-that-was-missing-and-how-it-hid)
10. **Carry virtual-geometry UV2 as a tail of the vertex arena (`SSBO_VIRTUAL_VERTICES`, 39), not a new binding.** `SSBO_BONE_PULL` (63) is ignored on Vulkan (`VulkanRendererAPI::AssembleRootData` resolves 57/63 from VAO streams, and the mesh-shader route has no VAO); every number 0..79 is claimed and 80 is Mesa's ceiling ([ssbo-binding-cap-is-80-on-mesa.md](ssbo-binding-cap-is-80-on-mesa.md)). Layout: `SlotCount * SlotVertexCapacity` vertices then `SlotCount * SlotVertexCapacity / 4` uv2 elements (four pairs per 32-byte element), +12.5% and only when a mesh carries UV2. [Details](lightmap-receiver-identity-details.md#virtualgeometry-the-uv2-rides-the-vertex-arena-because-no-binding-was-available)
11. **Keep both addressing invariants.** `VirtualMeshRegistry::LoadPage` starts every page at slot-local index 0, and `m_SlotVertexCapacity` rounds up to a multiple of 4. The math is in `VirtualLightmapUVPacking.h` with a GLSL twin in `include/VirtualDrawInfo.glsl` (`oloVirtualLightmapUVElement` / `oloVirtualLightmapUVLane`); change both. `u_VirtualLightmapUVBase` rides the draw-info UBO's first spare pad word, 0 meaning no tail. [Details](lightmap-receiver-identity-details.md#two-invariants-make-the-addressing-exact--do-not-break-either)
12. **Guard the UV2 fetch twice.** `u_VirtualLightmapUVBase != 0` (a buffer-device-address read has no bounds; amendment (89) device loss) and `LightmapScaleOffset.x > 0.0`. `SubmitVirtualMesh` refuses a region unless `MeshHasLightmapUVs(handle)`, and `EditorLayer::BakeLightmaps` calls `VirtualMeshRegistry::Invalidate` on every unwrapped mesh so the DAG re-cooks with the stream (`VirtualMeshBuilder` attributes 7 floats, `.OVGM` v3). [Details](lightmap-receiver-identity-details.md#the-fetch-is-guarded-twice-and-both-guards-are-safety)
13. **Sample UV2 in all three virtual-geometry rasterizers and in the fallback.** Hardware MDI, `VK_EXT_mesh_shader` and the compute software rasterizer (`VirtualVisibilityResolve.glsl`, perspective-correct barycentrics as for UV0) all write RT5; `Scene.cpp` passes the same region to the `virtualGeometryEnabled == false` fallback. `LightmapVirtualBleedRoom.VirtualGeometryReceivesBakedGIOnBothSidesOfTheToggle` proves it. [Details](lightmap-receiver-identity-details.md#all-three-rasterizers-sample-and-so-does-the-fallback)
