# The Actions cache store is a fixed budget, and every key must fit in it

Rules for adding, keying, saving or sizing a GitHub Actions cache entry. Applies to: `.github/workflows/**`, `.github/actions/**`, `cache-prune.yml`. Issue #1073.

## Rules

1. **Save any key ending in `-<run_id>` through `.github/actions/save-cache-pruned`.** Such keys are append-only; the action asks the API whether the save landed and, if not, deletes this ref's older entries under the same prefix and retries. Set `prefix` to the key minus its `-<run_id>-<attempt>` tail and grant the job `actions: write`. [Details](actions-cache-budget-details.md#adding-a-cache-to-this-repo)
2. **Never save a large cache on a `pull_request` run.** The entry is scoped to `refs/pull/N/merge`, readable by that one PR, and charged to the repository while the PR is open. Gate saves on `github.event_name != 'pull_request'` unless the entry is a few MiB or holds something the default-branch snapshot lacks. [Details](actions-cache-budget-details.md#six-open-prs-do-not-fit-in-a-10-gb-store)
3. **Treat a refused save as an outage, not a warning.** Past the cap (or the Actions budget) the whole store goes read-only; `actions/cache/save` reports a `warning` and exits zero. Read "Cache not found" and "Cache reservation failed" lines. A budget of $0 against a raised cap reproduces the bug. [Details](actions-cache-budget-details.md#the-cap-is-a-wall-not-an-eviction-threshold)
4. **Strip content hashes when grouping entries for pruning, and test the strip against a real live key.** Run the workflow's own `sed` over the live key list and count the groups; the `-<ImageVersion>` strip never fired because the example in its comment had two parts and real values have three (`20260907.229.1`). [Details](actions-cache-budget-details.md#why-the-existing-defences-did-not-hold)
5. **Confirm `cache-prune.yml`'s prefix regex strips your key's varying part (`-[0-9a-f]{32,}$`).** A non-hex part, such as the Vulkan SDK version, is not stripped; a bump orphans the old entry until the 30-day `last_accessed_at` age-out. Check the real read cadence before shortening that age-out (a prefix went a fortnight unread). Size the key shape to the entry. [Details](actions-cache-budget-details.md#the-janitor-could-not-collect-the-biggest-orphan)
6. **Spend the store only on GitHub-hosted jobs that run on a pull request.** Self-hosted jobs use local-disk caches (no save step, no ref scoping, no cap); nightlies are on nobody's critical path. A self-hosted runner using `actions/cache` still spends the shared cap. List which jobs are hosted and PR-triggered before allocating anything. [Details](actions-cache-budget-details.md#who-actually-has-a-claim-on-the-cap)
7. **Add a new cache's steady size to the arithmetic table and check the total clears the limit.** The cap is 25 GB since 2026-09-09; the binding number is `cache-prune.yml`'s working ceiling of 20000 MiB. Size the margin from the largest single entry, not a percentage; if the steady set leaves no room for the largest snapshot, no key design helps. [Details](actions-cache-budget-details.md#the-arithmetic-so-the-next-person-does-not-have-to-re-derive-it)
8. **Move the working ceiling only with the real cap; never raise it under a fixed cap to quiet the alarm.** `cache-prune.yml` fails when the post-sweep store exceeds the ceiling because the fleet outgrew the cap. If a budget is tighter than the cap, derive the ceiling from the budget. [Details](actions-cache-budget-details.md#the-arithmetic-so-the-next-person-does-not-have-to-re-derive-it)
9. **Set an sccache cap above the object set, and measure the set with `du -sm "$SCCACHE_DIR"` at an oversized probe cap.** `--show-stats` rounds (it printed "1 GiB" for 1084 MiB) and reports zeros if the server exited (#1082). A cap that fills lands at 82-91 % of the cap in the store; treat the cap as the bill. Measure a lineage again before calling its size settled (a fresh lineage is smaller than a steady one). See [sccache-cap-vs-object-set.md](sccache-cap-vs-object-set.md). [Details](actions-cache-budget-details.md#the-arithmetic-so-the-next-person-does-not-have-to-re-derive-it)
10. **Pin whatever a cache key is hashed over.** sccache hashes the compiler binary; a rolling apt snapshot clang made three entries hit 0.00 % while still restoring (3741 MiB). The hosted Linux arm now installs LLVM 23.1.0 at `/opt/llvm-23.1.0` with the version in the key. Include the Vulkan SDK version in sccache keys that reach Vulkan headers. [Details](actions-cache-budget-details.md#a-cache-can-be-worth-removing-and-this-one-was-worth-3741-mib)
11. **Before adding a cache, check what existing ones return.** Read `created_at`, `last_accessed_at` and the hit rate; a 0 %-hit entry costs quota, download time and room. Accept a cache change on the "Cache hits rate" line of the second nightly after it lands, not on a green check. Do not assume one cause explains every cold cache; check written and read separately. [Details](actions-cache-budget-details.md#the-other-half-of-1073)
12. **A cache is only as warm as its default-branch producer's cadence; judge a warm by which translation units hit.** Only default-branch runs produce; decay follows source drift (~12 merges a day). Use `scripts/Report-NinjaBuildTail.ps1` (reads `.ninja_log`) because the `Mcp*.cpp` objects run serialized at the end. [Details](actions-cache-budget-details.md#what-happened)
13. **Warm with a build-only `push: master` run; it costs runner time, not cap.** Entries stay one per (lineage, ref) via `save-cache-pruned`. Keep the `push` and `schedule` lanes in separate concurrency groups (`github.event_name` in the group) so a merge cannot cancel a pending nightly. [Details](actions-cache-budget-details.md#warming-costs-runner-time-not-cap)
14. **Retire the schedule when you retire the question.** A finished workflow's cache is still charged (`flaky-repro-281` held 886 MiB). A `workflow_dispatch` on a `feature/*` branch banks about 1.7 GiB against that branch ref until `cache-prune.yml` sweeps it. [Details](actions-cache-budget-details.md#adding-a-cache-to-this-repo)
15. **If `OLO_WINDOWS_SELF_HOSTED` is flipped, redo the claim table.** The two Windows sccache entries then leave the store on the PR path (ADR 0019). UBSan/TSan Linux saves stay gated on `github.event_name != 'pull_request'`; re-check that gate first if either arm gets a PR-ref save. [Details](actions-cache-budget-details.md#who-actually-has-a-claim-on-the-cap)
16. **Size MSVC Release sccache from unique objects of a complete build, then budget concurrent saves at full cap.** Release uses 3200M (2070 objects, 2688.31 MiB measured, #1584); the stress case of three snapshots plus the legacy one and rotations leaves 673 MB. Do not schedule extra branch producers or rotate all lineages together. Remeasure after graph, image or dependency changes. [Details](actions-cache-budget-details.md#2026-10-11-msvc-release-capacity)
