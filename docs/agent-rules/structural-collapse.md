# Progressive structural collapse (issue #786)

A set of `StructuralNodeComponent` pieces hold each other up; when one leaves, whatever loses its path to an anchor comes down after it. Read before touching `StructuralGraph`, adding a piece to a structure, or wondering why a wall did or did not fall. Design decision (derived adjacency, not authored links): [ADR 0021](../adr/0021-structural-connectivity-is-derived-from-collider-adjacency.md). Debris it feeds: [destructible-debris.md](destructible-debris.md).

## Rules

1. **Mark anchors explicitly with `m_Anchor = true`.** A piece is stable iff an anchor reaches it along support edges; nothing is anchored by being low, static or on the ground. An unanchored structure is not detected until something breaks, then the whole wall comes down at once. `StructuralGraph::SolveUnsupported` logs "a structure of N pieces (lowest id X) has no StructuralNodeComponent::m_Anchor left" once per structure; read the log before the solver. [Details](structural-collapse-details.md#anchors-are-explicit-a-structure-with-none-stands-until-it-is-touched-then-vanishes)
2. **Keep same-course neighbours supporting each other both ways.** The lower piece supports the higher; pieces whose centres are within `kLevelToleranceFraction` (0.25) of their combined vertical half-extents are on the same course. Without the mutual edge no lintel, arch or overhang stands. [Details](structural-collapse-details.md#same-course-neighbours-support-each-other-and-that-is-deliberate)
3. **Do not simplify the 0-1 BFS back to reachability.** A vertical edge costs 0, a same-course edge 1; a piece is stable only while its cheapest path from an anchor stays within its `m_MaxLateralSpan` (default 3), and an out-of-budget piece relays nothing. With free lateral transfer a wall vanishes in one go. If a structure refuses to collapse, check `m_MaxLateralSpan` and unnoticed same-course paths first. [Details](structural-collapse-details.md#sideways-load-is-charged-for-or-a-wall-is-all-or-nothing)
4. **Adjacency needs a shared face: world AABBs within `m_ContactMargin` (default 5 cm) on all three axes and real overlap on at least two.** The two-axis rule stops a corner or edge touch counting as support. [Details](structural-collapse-details.md#adjacency-is-a-shared-face-and-the-query-radius-has-to-allow-for-the-margin-on-the-diagonal)
5. **Make the spatial-hash query radius include `margin * sqrt(3)` on the diagonal.** The margin applies per axis, so the widest overlapping centre distance is `|he_i + he_j + margin*(1,1,1)|`; otherwise diagonal pairs silently drop. `StructuralGraph::Rebuild` does this; a rewrite must too. [Details](structural-collapse-details.md#adjacency-is-a-shared-face-and-the-query-radius-has-to-allow-for-the-margin-on-the-diagonal)
6. **Do not rely on component ordering for dynamic release; keep `JoltBody::CanBecomeDynamic()` and the body rebuild.** Jolt allocates `MotionProperties` at creation only; `SetMotionType(Dynamic)` on a static body without them asserts. `JoltBody::CreateBodySettings` sets `mAllowDynamicOrKinematic` for entities carrying `StructuralNodeComponent`, but a runtime-added `Rigidbody3DComponent` before the node component builds the body without it (prefab spawns, hand-assembled test pieces). [Details](structural-collapse-details.md#a-static-piece-cannot-be-made-dynamic-unless-it-was-built-expecting-to-be)
7. **`ReleaseToPhysics` must re-derive the object layer with `SetCollisionLayer(GetCollisionLayer())` after switching motion type.** It looks like a no-op; skipping it leaves the piece on `NON_MOVING` and the collapse falls through the ground. [Details](structural-collapse-details.md#a-detached-piece-goes-to-moving-not-debris)
8. **Do not call `SetToDebrisLayer()` on a detached piece.** It goes to MOVING so rubble can pile up and hit the player; `ObjectLayers::DEBRIS` collides with neither the character nor other debris. The chunks it later shatters into go to `DEBRIS` via the #459 path. [Details](structural-collapse-details.md#a-detached-piece-goes-to-moving-not-debris)
9. **Run the collapse inside `DestructibleSystem::OnUpdate`, in phases; no separate scheduler node.** Phase 0 advances the collapse state machine (condemn, detach, fall, set `m_PendingBreak`); 1 collects breaks; 1b re-solves islands that lost a piece; 2–4 are the #459 debris steps. Phases 0 and 1b write fields only; structural work stays in phases 3 and 4 behind the post-fence pin. [Details](structural-collapse-details.md#the-collapse-runs-on-the-existing-destructible-node-in-phases)
10. **Remove a piece from the graph only when it detaches, not when condemned.** That is what makes the collapse cascade one ring at a time. [Details](structural-collapse-details.md#the-collapse-runs-on-the-existing-destructible-node-in-phases)
11. **Keep the solve island-scoped and the scratch stamped.** A break re-floods only components that lost a piece, O(island); `LastSolveVisitedNodes` reports it and `StructuralCollapseTest.ASolveVisitsOnlyTheIslandThatLostAPiece` pins it. The build is a full O(N log N) pass. [Details](structural-collapse-details.md#what-is-island-scoped-and-what-is-not)
12. **Trigger rebuilds by the order-independent signature, not by invalidation calls at mutation sites.** It covers every piece's UUID plus `m_Anchor`, `m_ContactMargin`, `m_MaxLateralSpan`, so a same-count swap (`AddingAndRemovingAPieceInOneTickStillInvalidatesTheGraph`) and retuning from the inspector, Lua, MCP or C# both rebuild. [Details](structural-collapse-details.md#what-is-island-scoped-and-what-is-not)
13. **Keep `m_State` outside the signature,** since a detaching piece is tracked in place by `MarkRemoved`; folding it in would rebuild every collapse tick. Standing-piece transforms are also not covered (nothing moves them; folding them in rebuilds every tick while debris falls). [Details](structural-collapse-details.md#what-is-island-scoped-and-what-is-not)
14. **Derive aliveness from each piece's own `m_State` on rebuild;** do not carry the old `Alive` array across, or a mid-collapse rebuild resurrects fallen pieces. [Details](structural-collapse-details.md#what-is-island-scoped-and-what-is-not)
15. **Touch every binding for `StructuralNodeComponent`.** Scene YAML is generated; hand-write `SaveGameComponentSerializer::Serialize` + `REGISTER_SAVE_COMPONENT` (persists collapse state; out-of-range state byte on load restores as `Stable`), the Lua usertype (`LuaScriptGlue_Core.cpp` + `REGISTER_COMPONENT`, `state` read-only), and the editor inspector and Add Component entry (`SceneHierarchyPanel.cpp`). [Details](structural-collapse-details.md#cross-binding-what-structuralnodecomponent-needed)
16. **Address pieces by UUID in tests, never by a stored `Entity`.** A collapsing piece is destroyed and `HasComponent` on a destroyed entity is an EnTT assert. Tests live in `OloEngine/tests/Functional/Gameplay/StructuralCollapseTest.cpp`. [Details](structural-collapse-details.md#where-the-contract-is-pinned)
