# vcpkg dependency management

How third-party dependencies are resolved since issue #773, and the traps that cost time, several of which fail silently. Read before adding, removing or version-bumping a dependency, and before touching `vcpkg.json`, `cmake/triplets/` or `cmake/overlay-ports/`.

## Rules

1. **Set `VCPKG_ROOT` before configuring, in the current shell too.** `setx VCPKG_ROOT D:\vcpkg` persists only for future shells; also set `$env:VCPKG_ROOT`. A configure without it stops at the guard in the root `CMakeLists.txt`. Do not clone vcpkg shallow: an `"overrides"` entry that holds a port at an older version needs the full history (`git fetch --unshallow`). [Details](vcpkg-dependency-management-details.md#setup-one-time-per-machine)
2. **Run `git -C $VCPKG_ROOT config core.fsmonitor false`.** With fsmonitor on, an open daemon handle makes vcpkg's `.tmp` checkout rename fail with a file-lock error. `.github/actions/setup-vcpkg` does this for CI. [Details](vcpkg-dependency-management-details.md#trap-1--corefsmonitor-makes-vcpkg-fail-with-a-file-lock-error)
3. **Use the triplet `x64-windows-static-md` (static libs, dynamic CRT), never `x64-windows-static`.** A CRT mismatch is heap corruption at runtime, not a link error. [Details](vcpkg-dependency-management-details.md#trap-2--the-crt-triplet-is-static-md-not-static)
4. **Build ports once, with cl.exe, for both Windows trees; do not add a clang-cl triplet back.** Ports built by clang-cl broke MaterialX (`MeshInterchangeTest.MaterialXReadsStandardSurfaceFactors`) and libsodium and doubled the install cost. If a chainloaded triplet returns, use `VCPKG_ENV_PASSTHROUGH_UNTRACKED`, not `VCPKG_ENV_PASSTHROUGH`, which hashes the value (e.g. `PATH`) into the ABI and silently misses the cache. [Details](vcpkg-dependency-management-details.md#trap-3--build-ports-once-with-clexe-for-both-windows-trees)
5. **Give every new project-local configuration a `CMAKE_MAP_IMPORTED_CONFIG_<CONFIG>` line.** vcpkg installs only Debug and Release; `Dist` without `CMAKE_MAP_IMPORTED_CONFIG_DIST "Release;"` (in `cmake/SetupConfigurations.cmake`) links debug third-party libs into release code. [Details](vcpkg-dependency-management-details.md#trap-4--a-project-local-configuration-silently-links-debug-third-party-libs)
6. **Check every `set()` of a dependency option against the dependency's own `option()` declarations.** A wrong name never warns: `JPH_CROSS_PLATFORM_DETERMINISTIC` is a compile definition; the Jolt option is `CROSS_PLATFORM_DETERMINISTIC`. When moving a dependency to a port, diff what its defaults gave you against the manifest feature list (Jolt needs `debugrenderer` and `profiler` features for `JPH_DEBUG_RENDERER` / `JPH_PROFILE_ENABLED`). [Details](vcpkg-dependency-management-details.md#a-dependencys-option-names-are-part-of-its-contract--verify-them-dont-assume)
7. **"Overlay found" does not mean the option took effect; read the port's CMake cache log.** `info: installing overlay port from here` only says the directory was located. [Details](vcpkg-dependency-management-details.md#trap-5--the-overlay-was-found-is-not-the-option-took-effect)
8. **When adding a port, check what else read the variables `find_package` of that name sets.** `vulkan-headers` redirected `find_package(Vulkan)` and `Vulkan_INCLUDE_DIR`, breaking `spirv_cross/` includes; the fix is `OLO_VULKAN_SDK_INCLUDE_DIR` from `$ENV{VULKAN_SDK}`. [Details](vcpkg-dependency-management-details.md#trap-6--installing-a-port-shadows-a-find_package-you-did-not-intend-to-move)
9. **Batch triplet edits.** The triplet file's contents feed every port's ABI hash; one edit rebuilds all packages for that triplet (43 on MSVC). [Details](vcpkg-dependency-management-details.md#trap-7--editing-a-triplet-invalidates-every-package-built-with-it)
10. **To make one header win over an installed SDK, stage it into a private directory under the build tree; never reorder `<vcpkg_installed>/<triplet>/include`.** That root is SYSTEM, MSVC emits `-external:I`, and every `/I` is searched first. Stage into the build tree, not `OloEngine/vendor/` (`OLO_WITH_VULKAN` does this for `vulkan/` + `vk_video/`). Verify by reading the include list in `build\OloEngine\src\OloEngine.vcxproj`, not the CMake source; local green proves nothing when the dev box matches the version CI varies. [Details](vcpkg-dependency-management-details.md#trap-8--you-cannot-out-order-the-shared-vcpkg-include-root)
11. **After moving a dependency to a port, diff its `INTERFACE_COMPILE_DEFINITIONS`.** `grep INTERFACE_COMPILE_DEFINITIONS <vcpkg_installed>/<triplet>/share/<pkg>/*.cmake` and compare with the old wiring; newly ON options are un-reviewed behaviour changes (#787: cpp-httplib's `CPPHTTPLIB_USE_NON_BLOCKING_GETADDRINFO` crashed TSan with a bare SIGSEGV). To drop one definition, `list(FILTER ... EXCLUDE REGEX ...)` the property; never overwrite it. A TSan thread with no `__tsan_thread_start_func` frame is unknown to TSan. [Details](vcpkg-dependency-management-details.md#trap-9--a-ports-usage-requirements-can-switch-on-behaviour-the-old-wiring-never-had)
12. **Reproduce a Linux-only sanitizer crash in WSL2 Ubuntu 24.04, through `build-lock.ps1`.** Clone vcpkg without `--depth 1`; link with `-lstdc++exp` locally. Pass `handle_segv=0` in `TSAN_OPTIONS` so the debugger gets the fault. Full recipe in the details file. [Details](vcpkg-dependency-management-details.md#reproducing-a-linux-only-sanitizer-crash-without-ci)
13. **Put a one-port build exception in the triplet (`if(PORT STREQUAL "somelib")`), not in a forked portfile.** Use an overlay port only when the port's options are wrong. [Details](vcpkg-dependency-management-details.md#per-port-exceptions-live-in-the-triplet-not-in-a-forked-portfile)
14. **Keep the two overlay ports, `joltphysics` and `gamenetworkingsockets`, in `cmake/overlay-ports/` as minimal diffs and re-diff after every baseline bump.** `joltphysics` sets `CROSS_PLATFORM_DETERMINISTIC=ON`; `gamenetworkingsockets` sets `USE_CRYPTO=libsodium`, `ice` off by default and explicit `sodium_*` cache seeding. [Details](vcpkg-dependency-management-details.md#the-two-overlay-ports-we-own)
15. **Check the registry version against the pin before calling a move clean.** Not moved: sol2, lua (5.5.1 vs 5.4.7), stb (an image decoder fed untrusted files), imguizmo (would link two ImGui copies), FFmpeg, OpenUSD (`ONLY_DYNAMIC_LIBRARY`). A header-only library is never worth a version regression. [Details](vcpkg-dependency-management-details.md#what-did-not-move-and-why)
16. **Do not hand-add per-config Tracy defines on top of `Tracy::TracyClient`.** The port exports `TRACY_ENABLE;TRACY_ON_DEMAND` in every configuration, and 0.13.1 has no mangled symbol to catch a mismatch. entt is 3.16.0 (include `<entt/entt.hpp>`). [Details](vcpkg-dependency-management-details.md#what-moved-on-a-second-pass-and-the-version-cost-of-each)
17. **Attribute a golden-image failure with a full-precision metric comparison.** A metric identical to 17 significant figures across a dependency swap exonerates that dependency; a failure that passes in isolation is order-dependent state, not your diff. [Details](vcpkg-dependency-management-details.md#attributing-a-golden-image-failure-to-a-dependency-swap)
18. **Keep `MeshInterchangeTest.MaterialXReadsStandardSurfaceFactors` when touching assimp or MaterialX.** MaterialXFormat's pugixml 1.9 and assimp's pugixml 1.16 merge under `/FORCE:MULTIPLE`; link order is not the lever. Check what a port unbundles before moving a dependency in a forced merge. [Details](vcpkg-dependency-management-details.md#the-assimpmaterialx-pugixml-merge-is-a-live-hazard--check-it-when-you-touch-either)
19. **Expect vcpkg to win on cache hits, not cold builds, and to cost disk.** Cold install is slower than FetchContent (19 min 52 s vs 6 min 26 s); restore is 27 s; about 8 GB of installed trees per worktree. Measure before assuming otherwise. [Details](vcpkg-dependency-management-details.md#cost-characteristics--measure-dont-assume)
20. **In CI-adjacent scripts, never `grep -q` the output of `vcpkg help binarycaching` under `pipefail`.** It SIGPIPEs vcpkg and reports the provider absent; use `grep -E ... > /dev/null`. `.github/actions/setup-vcpkg` is the single CI wiring point. [Details](vcpkg-dependency-management-details.md#ci)

## Commands and checks

```powershell
# Force a genuine from-scratch port build (bypass the binary cache):
$env:VCPKG_BINARY_SOURCES = "clear"
# Cache-hit only, fail instead of building:
$env:VCPKG_BINARY_SOURCES = "clear;files,$env:VCPKG_DEFAULT_BINARY_CACHE,read"
```

`vcpkg install --dry-run` prints the resolved plan in seconds; run it first after editing the manifest. The install log says "Restored N package(s)" for a hit, "Building <port>" for a cold build.
