# Testing Architecture

Operational rules for adding, moving, renaming or deleting a test. Applies to: `OloEngine/tests/**`.
Philosophy, value heuristic and the per-layer reference live in [../testing.md](../testing.md); read it before adding a test.

## Rules

1. **Classify every new test before writing code: exactly one renderer layer (L1-L11, plumbing, cullinglod, shaderpipe, integration, meta) or the `"Functional"` tag.** If you cannot classify it you are writing a symptom check; design the contract first. Functional tests drive a real `Scene::OnUpdateRuntime`, live under `OloEngine/tests/Functional/<Subsystem>/`, inherit `OloEngine::Functional::FunctionalTest`, and pin one seam per file. [Details](testing-architecture-details.md#1-pick-a-classification-before-writing-code)
2. **Classify every `.cpp` that declares `TEST` / `TEST_F` / `TEST_P` / `TYPED_TEST`.** Preferred: `// OLO_TEST_LAYER: <id>` near the top (a layer id, `Functional`, or `unit`); fallback: an entry in `file_layer_map` in `OloEngine/tests/scripts/test_catalogue.json`. One or the other, not both (the marker wins). The `test-catalogue-classified` hook fails the commit otherwise. [Details](testing-architecture-details.md#2-the-registration-contract-non-negotiable)
3. **Never hand-edit `docs/test-catalogue.{renderer,functional,unit}.md`.** They are git-ignored and regenerated by `python OloEngine/tests/scripts/generate_test_catalogue.py`; commit only the `.cpp`. [Details](testing-architecture-details.md#2-the-registration-contract-non-negotiable)
4. **Land a feature with tests at the layers its surface dictates.** Math/physics contract: L1. New GLSL helper: L2 (`ShaderUnit_*.glsl`). New CPU-GPU type or format: L3. Binds GL state: L4 `GLStateGuard` region. New render-graph pass/resource/edge: L5. Hot path: L6 with a `perf_baselines.txt` entry and the anti-flake helper. Visible pixels: L8 golden, only after L1-L4 pin the contract. External data parser: L11 fuzz harness plus seed corpus in `OloEngine/tests/Fuzzing/corpus/`. Crosses subsystems: also a Functional test. [Details](testing-architecture-details.md#3-when-adding-a-new-engine-feature-add-tests-in-lockstep)
5. **Reject the anti-patterns.** Golden-only coverage; expected values with no derivation or citation; raw `EXPECT_LT(elapsed_ns, constant)` timing asserts (use the baseline path); tests needing a specific GPU vendor; unregistered test files. [Details](testing-architecture-details.md#4-anti-patterns-to-reject)
6. **Never name the system temp root in a test; use `TestTempDir.h`.** `OloEngine::Tests::TempDir()`, `TempDir("staging")`, `TempFile("cfg.yaml")` are keyed by process and gtest case. Never share a fixed path, port or named OS object between cases; never `remove_all()` a fixed shared location in a fixture. The `test-temp-dir-isolated` hook (`check_temp_dir_isolation.py`) fails direct `std::filesystem::temp_directory_path()`; opt out only with `// OLO_TEMP_DIR_OK: <reason>`. See [shared-temp-dir-test-isolation.md](shared-temp-dir-test-isolation.md). [Details](testing-architecture-details.md#61-never-share-a-mutable-os-resource-between-test-cases)
7. **Serialize a test that loads and invalidates a shared model in the mesh cache.** Add its `Suite.Case` to the `OLO_MESH_CACHE_TESTS` filter in `OloEngine/tests/CMakeLists.txt` (`RESOURCE_LOCK "olo_mesh_cache"`). Put a new heavy or long test in `OLO_HEAVY_TESTS` by suite pattern; a new light test needs nothing. [Details](testing-architecture-details.md#62-shared-resources-that-cant-be-process-keyed--serialize-in-cmake)
8. **Leave `glGetError()` empty when a GPU test returns.** Unbind textures/buffer slots/programs (`glBindTextureUnit(0, 0)`, `glBindBufferBase(..., 0)`, `glUseProgram(0)`) before the `glDelete*` calls; drain a provoked error with `Utils::DrainGLErrors()`; prefer removing the cause. The global listener `GLErrorStateCheck` fails the source test with `GL error state not clean after test: left <ENUM>`; fix the named test, never drain in its victim. [Details](testing-architecture-details.md#64-gl-error-state-hygiene--leave-glgeterror-clean-issue-485)
9. **A lazy GPU-resource loader must not cache a non-renderable result when no GL context is bound.** Retain the CPU data and upload on first use with a context (model: `SlugFontProcessor::EnsureGpuTextures`), or do not cache until the upload succeeds. [Details](testing-architecture-details.md#65-lazy-loaded-gpu-resources-a-headless-first-touch-must-not-cache-a-non-renderable-state-issue-520)
10. **Call `Utils::UnbindProgramIfCurrent(programId)` before any `glDeleteProgram` that might still be current**, including inside a `FrameResourceManager::SubmitForDeletion` lambda. Never delete a GL object without checking whether it is bound on its binding point. `GLClearProgramGuard` checks `glIsProgram()` before restoring. [Details](testing-architecture-details.md#66-deferred-deletion-of-a-still-current-gl-program-is-a-landmine-not-a-leak-issue-625)
11. **Compute (`.comp`) shaders in `ShaderHarness` compile under the OpenGL shaderc target with `SetAutoMapLocations(true)`; all other stages use Vulkan 1.2.** Compute samplers are exempt from `ShaderCrossConsistencyTest::SamplerBindingsHaveConsistentType`, but a compute texture name still needs a registered pattern in `ShaderReflectionBindingTest`. [Details](testing-architecture-details.md#67-headless-comp-coverage-in-shaderharness-compute-stages-need-a-different-shaderc-target-env-issue-627)
12. **Write screenshot tests with `EnableRendering(w, h)` on `RendererAttachedTest` and render via `RunFrames` or `RunEditorFrames`; never `DISABLED_`.** They skip cleanly without a GL 4.6 context (in the `--olo-rhi=vulkan` process, without a Vulkan device). `AssetSceneLoadTest` needs a live context too. [Details](testing-architecture-details.md#8-screenshot-and-scene-load-tests-run-in-the-normal-suite-issue-258)
13. **Run a scene-level contract on both backends as one `RendererAttachedTest` in two processes, the default one and `OloEngine-Tests --olo-rhi=vulkan` (a windowless `VulkanContext`); write a single-pass contract as a `VulkanPassSuite` tenant.** Never parameterise one fixture over both backends inside a process. Read back by RHI handle, name evidence with `TestRenderBackend::EvidenceName`, add the suite to `OLO_VK_SCENE_FILTER` in `vulkan-software.yml`, and anchor both backends to an analytic CPU reference, never to each other. [Details](testing-architecture-details.md#9-scene-level-vulkan-runs-in-a-second-process-a-single-pass-contract-stays-a-vulkanpasssuite-tenant-issues-1107-1556)
14. **A Vulkan tenant crosses the production seam and asserts the seam's per-backend answers outright.** Feed geometry through `RHI::AdjustProjectionForBackend`; take values from `RHI::NdcToWindowDepthScaleBias()` / `RHI::WindowSpaceFrontFaceSign()`; row order from `RHI::RenderTargetRowsAreBottomUp()`. Also assert e.g. `WindowSpaceFrontFaceSign() == -1` on Vulkan, because every `RHIProjectionSeam` member depends on one `BackendFlips()`. Model: `VulkanPassSuite.GroomStrandCoatCoversPixelsUnderTheVulkanClipConvention`. [Details](testing-architecture-details.md#what-cheap-means-concretely)
15. **A rendering feature touching a pass, shader or the projection seam adds a `VulkanPassSuite` tenant in the same PR.** Its scene evidence runs in the `--olo-rhi=vulkan` process too when the suite is ported; until it is, capture a live Vulkan frame in the PR body and say why. [Details](testing-architecture-details.md#10-every-rendering-feature-adds-pass-level-vulkan-coverage-and-a-run-says-whether-it-got-any-issue-1300)
16. **Start every device-gated Vulkan test with `OLO_VULKAN_DEVICE_OR_SKIP()`** (`OloEngine/tests/Rendering/VulkanTestSupport.h`), never an inline probe ladder or a bare `ProbeVulkanDeviceTestGate()` + `GTEST_SKIP`. It prints `EXERCISED`, `NOT EXERCISED` or `PARTIAL` after gtest's summary; read it before trusting a green run. No PR job runs the device-backed half on hardware; `.github/workflows/vulkan-software.yml` runs it nightly on lavapipe ([vulkan-software-driver-ci.md](vulkan-software-driver-ci.md)). [Details](testing-architecture-details.md#a-skipped-run-must-not-read-as-a-tested-one)
17. **When a GL-context test fails on your branch, run the same filter on a throwaway `origin/master` worktree first.** CI skips these tests, so parallel merges can break them unseen. Identical failures on master are a pre-existing break: fix in its own commit, say so in the PR body. [Details](testing-architecture-details.md#63-gpu-and-cpu-oversubscription-are-tolerated-not-isolated)
18. **When a concurrency test flakes on CI, exclude only the specific failing case with a tight regex and file an issue; never exclude a family.** There are no residual Task/Async exclusions. If physics tests flake under `-j`, add a ctest `RESOURCE_LOCK` / `PROCESSORS` property, not a lower global `-j`. [Details](testing-architecture-details.md#63-gpu-and-cpu-oversubscription-are-tolerated-not-isolated)
19. **Reproduce a CI-only core-starvation race with `scripts/repro-flaky-test.ps1`.** Set both `OLO_TASK_GRAPH_NUM_WORKERS=N` (affinity alone does not shrink `FScheduler`'s pool; CI-faithful: `2` with affinity `0x3`) and `--gtest_repeat=N` for step density. [Details](testing-architecture-details.md#reproducing-flaky-ci-only-core-starvation-races)
20. **Run tests from `OloEditor/` when possible** (what `ctest` uses). ctest runs mesh-cache and `OLO_HEAVY_TESTS` cases one per process, the rest one suite per process. [Details](testing-architecture-details.md#how-ctest-slices-the-binary-three-passes-one-process-each)
21. **Rebase goldens or perf baselines only after a deliberate visual change or hardware move.** [Details](testing-architecture-details.md#5-running-tests-locally)

## Commands and checks

```powershell
build\OloEngine\tests\Debug\OloEngine-Tests.exe --gtest_filter=SuiteName.TestName
<test binary> --olo-golden-rebase --gtest_filter=GoldenImage*
<test binary> --olo-perf-rebase --gtest_filter=PerfRegression*
build\OloEngine\tests\Debug\OloEngine-Tests.exe --gtest_filter=VulkanPassSuite.* --olo-require-vulkan
```

Single test, golden rebase, perf rebase, Vulkan run that fails without a device; for a scene suite on
the windowless Vulkan context add `--olo-rhi=vulkan`.
