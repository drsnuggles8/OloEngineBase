# Terrain GPU LOD quadtree — what breaks, and why none of it is loud

Rules for editing the GPU terrain LOD quadtree and picker (issues #714, #717). Applies to: `OloEngine/src/OloEngine/Terrain/TerrainGPUQuadtree.*`, `OloEngine/src/OloEngine/Terrain/TerrainQuadtree.*`, `OloEditor/assets/shaders/compute/Terrain*.comp`, `OloEditor/assets/shaders/include/TerrainQuadtreeCommon.glsl`, `OloEditor/assets/shaders/include/TerrainGpuDrivenVertex.glsl`, `OloEditor/assets/shaders/Terrain_{PBR,GBuffer,Depth}.glsl`.

## Rules

1. **Validate a `.comp` against the driver, not `glslc`.** `OpenGLComputeShader::Compile` passes GLSL straight to `glShaderSource` with no shaderc hop. Run the test that drives the pass and read the log line `Compute shader compilation failed (<name>)`; `glslc` is a quick first check only. [Details](terrain-gpu-lod-quadtree-details.md#6a-a-comp-never-goes-through-shaderc-on-the-gl-backend--so-glslc-does-not-validate-it)
2. **Never use GLSL reserved words as identifiers.** `packed` passed glslang but broke NVIDIA's front-end (all four kernels). Shadowing built-in functions (`step`, `distance`) is fine. [Details](terrain-gpu-lod-quadtree-details.md#6a-a-comp-never-goes-through-shaderc-on-the-gl-backend--so-glslc-does-not-validate-it)
3. **A hung test binary with flat CPU time is a shader compile assert.** `OLO_CORE_ASSERT` opens a `MessageBoxA` with no headless suppression, so it hangs. Confirm with `cdb -p <pid> -c "~0 kn 24; qd"`; `USER32!MessageBoxA` is four frames below your code. [Details](terrain-gpu-lod-quadtree-details.md#6a-a-comp-never-goes-through-shaderc-on-the-gl-backend--so-glslc-does-not-validate-it)
4. **Grep the scenes for the flag that gates a feature before trusting a green suite.** `TerrainComponent::m_TessellationEnabled` gates the whole quadtree path and no scene set it. Run `grep -rn "TessellationEnabled: true" OloEditor/SandboxProject/Assets/Scenes/`; keep `TerrainGpuLodTest.olo` enabled. [Details](terrain-gpu-lod-quadtree-details.md#1-the-bug-the-rewrite-found-first-a-feature-with-no-scene-and-therefore-no-coverage)
5. **Do not make `TerrainChunkManager::FindChunkForNode` smarter.** A node is not a chunk; the GPU path draws the node itself (one instance of a shared unit grid over the node's rect), so there is nothing to map. [Details](terrain-gpu-lod-quadtree-details.md#1-the-bug-the-rewrite-found-first-a-feature-with-no-scene-and-therefore-no-coverage)
6. **Keep crack-freedom a property of the vertex set.** Adjacent edges must produce exactly the same positions. `kPatchGridResolution` must stay a power of two (a `static_assert` pins it); `delta = max(0, myLevel - neighbourLevel)` must be clamped to `log2(K)` (`TerrainSeamMap.comp` clamps, `kMaxSeamDelta` is the twin); corners must stay fixed points (the +X/-X test runs before +Z/-Z in `oloTerrainSnapEdgeIndex`; re-derive if you reorder). [Details](terrain-gpu-lod-quadtree-details.md#2-crack-freedom-is-a-property-of-the-vertex-set-not-of-a-tessellation-factor)
7. **Only the finer side of a seam decimates.** If both sides snapped they would decimate to different grids and the seam would open. [Details](terrain-gpu-lod-quadtree-details.md#2-crack-freedom-is-a-property-of-the-vertex-set-not-of-a-tessellation-factor)
8. **Compare seam edges with exact equality, plus an anti-vacuous guard.** `TerrainGPUQuadtreeTest.AdjacentPatchEdgesShareExactlyTheSameVertexPositions` sweeps `TargetTriangleSize` `{8, 120, 600, 2400}` px and asserts at least one boundary joins two different levels. Any "adjacent things agree" test needs a second assertion that the interesting adjacency occurred. [Details](terrain-gpu-lod-quadtree-details.md#2-crack-freedom-is-a-property-of-the-vertex-set-not-of-a-tessellation-factor)
9. **Keep `TerrainSeamMap.comp` sampling one texel per edge.** Do not replace it with a min, max or mean; a quadtree edge cannot mix coarse and fine neighbours, so the point sample is exact and a mean is wrong. [Details](terrain-gpu-lod-quadtree-details.md#3-sampling-one-texel-per-edge-is-exact--do-not-improve-it-into-an-average)
10. **Do not mark frustum-culled nodes as split.** `TerrainNodeSelect.comp` returns early on a cull without touching the split map, which is intended; descending culled nodes would defeat culling. Edge artefacts at the frustum boundary are the place to look, but the fix is not "stop culling". [Details](terrain-gpu-lod-quadtree-details.md#4-a-frustum-culled-node-is-deliberately-not-marked-as-split)
11. **Do not stack hardware tessellation on the node grid.** The GPU path sets `TessFactors = vec4(1.0)`. For more triangles lower `TargetTriangleSize` or raise `kPatchGridResolution`; `min(myTess, neighbourTess)` is wrong for patches of different world extent. [Details](terrain-gpu-lod-quadtree-details.md#5-do-not-stack-hardware-tessellation-on-top-of-geometric-lod)
12. **`HasDispatched()` must not latch.** `TerrainChunkManager::SelectVisibleChunks` calls `ClearDispatched()` so the last path to run owns the frame and `OLO_TERRAIN_CPU_LOD=1` works. A third path clears the other two. [Details](terrain-gpu-lod-quadtree-details.md#6-hasdispatched-must-not-latch)
13. **Put a `MemoryBarrierFlags::Command` barrier between the kernel writing indirect args and `RendererAPI::DispatchComputeIndirect`.** Omitting it gives a one-frame-stale terrain. On Vulkan the argument buffer needs the indirect usage bit (checked by `ResolveIndirectBuffer`). [Details](terrain-gpu-lod-quadtree-details.md#7-indirect-compute-dispatch-did-not-exist-in-the-rhi-before-this)
14. **Pass `topology` to `DrawBoundElementsIndirect` explicitly; no default argument on a virtual.** A default is resolved from the static type, so an override can disagree with the base. [Details](terrain-gpu-lod-quadtree-details.md#7-indirect-compute-dispatch-did-not-exist-in-the-rhi-before-this)
15. **Keep the CPU and GPU descents identical so parity stays exact.** `TerrainQuadtree::BuildHeightPyramid` feeds both; the GLSL descent is a transcription of `TerrainQuadtree::SelectNode`. Do not add a term to one side, and do not loosen `TerrainGPUQuadtreeTest.GpuDescentSelectsTheSameNodesAsTheCpuQuadtree`. The GPU tree is not clamped to `TerrainLODConfig::MAX_LOD_LEVELS`, so parity holds only at equal depth. [Details](terrain-gpu-lod-quadtree-details.md#8-the-node-pyramid-is-shared-on-purpose-and-that-is-what-makes-parity-testable)
16. **Read clamped counts and poll overflow rarely.** Consumers read the value `TerrainCullArgs.comp` clamped; `PollOverflow()` is a `GetData` stall, so it reads at most once every 240 frames and warns once. The select kernel's per-child bound check keeps `PendingCount` from addressing stale slots. [Details](terrain-gpu-lod-quadtree-details.md#9-overflow-is-reported-not-asserted--and-the-report-costs-a-stall)
17. **Do not build a `TerrainData` in an L1 test.** `CreateFlat`/`GenerateProcedural`/`SetHeights` end in `UploadToGPU()` and fault (`0xc0000005`, no gtest stack) without a GL context. Use the `std::span<const f32>` overload of `TerrainQuadtree::BuildHeightPyramid` plus `TerrainQuadtree::BuildFromPyramid`. `TerrainCameraRelativeLODTest` (`CreateFlat(129, ...)`) still has the latent version. [Details](terrain-gpu-lod-quadtree-details.md#10-populating-a-terraindata-creates-a-gpu-texture--so-an-l1-test-must-not)
18. **Keep shadow casters on `GetVisibleChunks(...)` chunk meshes.** The GPU visible list is camera-culled; do not point the shadow pass at it. A correct fix needs a second GPU descent per cascade. [Details](terrain-gpu-lod-quadtree-details.md#11-shadow-casters-stayed-on-the-chunk-meshes)
19. **Hang the picker dispatch off `IsBuilt()`, not `m_TessellationEnabled`.** Picking (`TerrainGPUPicker`) must answer in every terrain scene; `TerrainGPUPickEvidenceTest` builds with `m_TessellationEnabled = false`. [Details](terrain-gpu-lod-quadtree-details.md#12-picking-rides-the-same-pyramid--and-must-not-ride-the-same-gate)
20. **Keep the pick resolve's Y clip to the inflated node AABB.** Unbounded Y spreads the per-lane sample budget over the whole ray; the inflation keeps the entry sample above the surface. [Details](terrain-gpu-lod-quadtree-details.md#12-picking-rides-the-same-pyramid--and-must-not-ride-the-same-gate)
21. **Keep `atomicMin` on `floatBitsToUint(t)` as the ordering.** Valid for `t >= 0`; the reset value `0xFFFFFFFF` makes "no hit" lose, and `TerrainGPUPickerLayoutTest` asserts it. [Details](terrain-gpu-lod-quadtree-details.md#12-picking-rides-the-same-pyramid--and-must-not-ride-the-same-gate)
22. **Sample the heightmap in `TerrainPickResolve.comp` with `texelFetch` transcribing `TerrainData::GetHeightAt`, not `texture()`.** The conventions differ by half a texel and the tolerance hides it; the evidence test asserts a surface residual at half a texel. [Details](terrain-gpu-lod-quadtree-details.md#12-picking-rides-the-same-pyramid--and-must-not-ride-the-same-gate)
23. **Write the pick march overflow flag `OLO_TERRAIN_PICK_OVERFLOW_MARCH` into `ResultFlags` with `atomicOr`, not `OverflowFlags`.** `TerrainPickArgs.comp` copies `OverflowFlags` into `ResultFlags` before the resolve dispatch, so reordering dispatches breaks it silently. Report overflow through an existing readback ring instead of adding a `GetData`. [Details](terrain-gpu-lod-quadtree-details.md#12-picking-rides-the-same-pyramid--and-must-not-ride-the-same-gate)

## Commands and checks

Get the real frame of a `0xc0000005` that gtest swallows (do not pass `-g`):

```powershell
& "<pkg>\amd64\cdb.exe" -y "srv*;<test dir>" `
  -c "sxe -c `"kn 22; q`" av; g" OloEngine-Tests.exe --gtest_filter=Suite.Case
```
